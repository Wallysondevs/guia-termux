Cola de adb — o controle remoto do celular rootado

O adb (Android Debug Bridge) é a ponte entre o terminal e o sistema Android: com ele você lista dispositivos ligados na USB/Wi-Fi, abre um shell no celular, lê logs e instala APKs. Na máquina da Ana o cenário é especial: o Pixel 7 Pro está rootado, então o adb root devolve um shell root — o dono do sistema inteiro. Nesta cola estão os comandos essenciais com a saída real do simulador ana@android.

Você vai aprender
  • O que é o adb e quando usar no Termux (o próprio celular fala com outro Android, ou com ele mesmo via PC).
  • adb devices — listar dispositivos; na máquina da Ana aparece R5CT20ABCPIXEL e o aviso de root.
  • adb root — subir o adbd como root num aparelho rootado (adbd is already running as root ✓).
  • adb shell … — rodar comandos dentro do celular (whoami → root, ls /data).
  • adb logcat — ler o log do sistema, e adb install app.apk — instalar app de fora.
  • Os riscos reais de root: por que só usar em aparelho de teste.

O cenário da Ana: um Pixel 7 Pro rootado na USB

Ana deixou o Depuração USB ligado no Pixel 7 Pro (Android 14) e conectou no computador — ou, no caso do Termux, o celular "enxerga" outro dispositivo Android. O primeiro comando de qualquer sessão adb é sempre o mesmo: ver quem está conectado.

$ adb devices
List of devices attached
R5CT20ABCPIXEL	device product:blueline model:Pixel_7_Pro device:blueline

Dispositivo rootado detectado ✓ (1 dispositivo)

O número de série R5CT20ABCPIXEL identifica o aparelho; device na frente significa que ele está online e aceitando comandos (se aparecer unauthorized, aceite a caixa de depuração na tela do celular).

adb root: o shell que vira root

Num celular sem root, o adb abre como usuário comum e o adb root é recusado (adbd cannot run as root in production builds). No Pixel da Ana, que roda uma build rootada, o adbd já sobe como root:

$ adb root
restarting adbd as root
adbd is already running as root ✓
$ adb shell whoami
root
$ adb shell ls /data
(root) acesso total a /data ✓
$ adb shell getprop ro.build.version.release
14

Repare na diferença brutal: dentro do Termux a Ana é u0_a231 (ana) (usuário comum do app), mas via adb shell no aparelho rootado ela vira root — capaz de ler /data inteiro, mudar qualquer configuração do sistema e instalar apps em silêncio. É o equivalente a sudo no PC, só que no celular.

Root é poder — e risco: com root, qualquer comando errado apaga dados de todos os apps, o sistema pode não bootar mais e apps maliciosos ganham acesso total. Use root só em aparelho de teste, nunca no celular do dia a dia com dados reais. Detalhes na aula Root no Android: su, magisk e riscos.

adb shell: rodar comandos dentro do celular

O padrão é adb shell COMANDO — dá para encadear vários com ponto e vírgula, e sem argumentos o adb shell abre um shell interativo dentro do aparelho:

$ adb shell whoami
root
$ adb shell "whoami; uname -a" 2>/dev/null || adb shell whoami
root
$ adb shell ls /data
(root) acesso total a /data ✓

No simulador, o adb shell responde os comandos clássico (whoami, getprop, ls /data) e ecoa os demais — no celular real a saída seria a de verdade.

adb logcat: ler o log do Android

Quando um app trava ou o Termux não abre, o logcat é a primeira coisa que se lê. Ele é um fluxo contínuo — no terminal real você para com Ctrl+C:

$ adb logcat
--------- beginning of main
I/ActivityManager: Displayed com.termux/.app.TermuxActivity
D/adbd: root shell conectado

Cada linha tem nível (I=info, D=debug, E=erro), a tag do componente e a mensagem. Para filtrar só erros no celular real: adb logcat *:E.

adb install: instalar APK pelo terminal

Baixou um APK no PC (ou no próprio Termux, com curl)? Instale sem encostar na tela:

$ adb install termux-api.apk
Success ✓ (app instalado via adb)

No mundo real, o adb install falha se a versão já instalada for mais nova (use -r para reinstalar e -d para downgrade). E lembre: APK de fonte duvidosa + root = combinação perigosa.

adb over Wi-Fi: celular falando com celular

O adb não precisa de cabo: com a Depuração por Wi-Fi ligada (Android 11+), um dispositivo fala com o outro pela rede local. No cenário da Ana, o Termux do celular dela alcança o próprio Pixel (ou outro Android na mesma rede) assim:

$ adb connect 192.168.1.42:5555
connected to 192.168.1.42:5555
$ adb devices
List of devices attached
R5CT20ABCPIXEL	device product:blueline model:Pixel_7_Pro device:blueline

Dispositivo rootado detectado ✓ (1 dispositivo)
$ ifconfig
wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>
        inet 192.168.1.42  netmask 255.255.255.0
        ether dc:a6:32:11:22:33

O IP 192.168.1.42 é o do próprio celular na rede Wi-Fi (quem entrega é o ifconfig — veja a aula Rede no celular). Depois do adb connect, todos os comandos funcionam igual ao modo USB.

Segurança: adb na rede é porta aberta. Qualquer um na mesma Wi-Fi pode mandar adb connect no seu IP se a depuração por rede estiver ligada — e num aparelho rootado isso significa shell root remoto. Desligue a depuração por Wi-Fi quando não estiver usando (adb disconnect para remover da lista).

Diagnóstico rápido quando o adb não vê o dispositivo

  1. adb devices mostra nada? Confirme o cabo/USB-C bom e a Depuração USB ligada nas Opções de desenvolvedor.
  2. Apareceu unauthorized? Aceite a caixa "Permitir depuração USB" na tela do celular.
  3. Still nothing? adb kill-server && adb start-server reinicia a ponte (no simulador: adb root já confirma que o adbd está de pé).
  4. Em produção (sem root), adb root responde adbd cannot run as root in production builds — comportamento esperado, não é bug.

O fluxo completo: do devices ao root em 4 comandos

Esse é o roteiro que a Ana roda toda vez que senta no PC para mexer no celular rootado dela — copie a sequência:

$ adb devices
List of devices attached
R5CT20ABCPIXEL	device product:blueline model:Pixel_7_Pro device:blueline

Dispositivo rootado detectado ✓ (1 dispositivo)
$ adb root
restarting adbd as root
adbd is already running as root ✓
$ adb shell whoami
root
$ adb shell "ls /data | head -3" 2>/dev/null || adb shell ls /data
(root) acesso total a /data ✓
$ adb logcat | tail -2
I/ActivityManager: Displayed com.termux/.app.TermuxActivity
D/adbd: root shell conectado

Repare que dá para encadear comandos dentro do adb shell "…" e filtrar a saída com | (no exemplo, tail -2 no logcat para ver só o fim). No simulador, o adb shell reconhece whoami, getprop e ls /data de verdade.

Pratique no terminal simulado

Missão 1 — ver dispositivos: rode adb devices e confirme que o Pixel 7 Pro da Ana (R5CT20ABCPIXEL) está rootado e online.

Missão 2 — virar root: rode adb root e depois adb shell whoami (deve imprimir root). Experimente também adb logcat e adb install app.apk.
