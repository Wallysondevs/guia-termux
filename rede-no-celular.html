Rede no celular: do Wi-Fi ao túnel reverso

O celular da Ana está no Wi-Fi de casa com o IP 192.168.1.42, rodando um servidor SSH na porta 8022 e um servidor web Python na 8080. Nesta aula você aprende a enxergar essa rede do próprio celular — ifconfig, ping, nmap localhost — e o truque que mais impressiona: publicar o site que roda no Termux na internet usando um túnel reverso com ngrok, sem precisar abrir nenhuma porta no roteador.

Você vai aprender
  • Como o celular pega IP no Wi-Fi: ifconfig mostra a interface wlan0 com inet 192.168.1.42;
  • Testar a internet com ping -c 1 8.8.8.8 (1 pacote transmitido, 1 recebido);
  • Enumerar as portas abertas no próprio celular com nmap localhost (8022 ssh, 8080 http);
  • Por que localhost no celular é o próprio celular — e a diferença para o IP do Wi-Fi;
  • Túnel reverso: ngrok http 8080 gera uma URL pública (*.ngrok-free.app) que chega no servidor do Termux;
  • Praticar tudo no terminal simulado ana@android.

O IP do celular no Wi-Fi: ifconfig

Quando o Pixel entra no Wi-Fi de casa, o roteador entrega a ele um IP privado via DHCP — no caso, 192.168.1.42. O comando ifconfig (ou ip addr) mostra exatamente isso, na interface wlan0 (a placa Wi-Fi):

$ ifconfig
wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>
        inet 192.168.1.42  netmask 255.255.255.0
        ether dc:a6:32:11:22:33

lo: inet 127.0.0.1
ifconfig
o comando clássico que lista as interfaces de rede e seus endereços IP
wlan0
a interface Wi-Fi do celular ("wireless LAN 0") — é por ela que o tráfego sai para a rede local e a internet
inet 192.168.1.42
o endereço IPv4 que o roteador deu ao celular na rede local (192.168.x.x é uma faixa privada)
lo
a interface de loopback (127.0.0.1): o "endereço de si mesmo", usado pelo localhost

Esse IP é o que você usa para acessar o celular de dentro da mesma rede: do PC, ssh ana@192.168.1.42 -p 8022 (aula sshd no Termux). Ele muda toda vez que o celular reconecta — dá para fixar um IP estático nas configurações de Wi-Fi do Android ou pelo MAC no roteador.

Testando a conexão: ping

O ping manda um pacote ICMP de eco para um endereço e mede se ele voltou. É o "alô, tem alguém aí?" da rede:

$ ping -c 1 8.8.8.8
PING 8.8.8.8: 56 data bytes
64 bytes: icmp_seq=0 ttl=117 time=23.4 ms
1 packets transmitted, 1 packets received, 0.0% packet loss ✓

O 8.8.8.8 é o DNS público do Google — um alvo seguro para teste porque ele sempre responde. -c 1 limita a 1 pacote (senão o ping roda até você apertar Ctrl+C). Se o ping falha, o problema é antes da aplicação: Wi-Fi conectado? Roteador ligado? Modo avião? Se o ping ao 8.8.8.8 funciona mas um site não abre, aí o problema é DNS — teste ping -c 1 google.com.

Portas abertas no próprio celular: nmap localhost

Um celular com Termux rodando sshd e um servidor web é, na prática, um mini servidor. O nmap lista as portas TCP abertas — e rodando contra localhost (127.0.0.1, o próprio aparelho), ele mostra o que está escutando no celular:

$ nmap localhost
Starting Nmap 7.94 (simulado)
Host 192.168.1.42 is up.
PORT     STATE SERVICE
8022/tcp open  ssh
8080/tcp open  http
Nmap done: 1 IP address scanned ✓

As duas portas são as nossas velhas conhecida: 8022 é o sshd (aula sshd no Termux) e 8080 é o python -m http.server 8080 (aula Servidor web no celular). Rodar nmap localhost é o jeito rápido de confirmar que os serviços subiram — e, no celular rootado, dá para ir além: com root, o nmap consegue fazer scan SYN furtivo e varredura de redes inteiras a partir do próprio aparelho (cuidado: só em redes suas ou autorizadas — veja Laboratório ético).

Cuidado com o que você escaneia. Rodar nmap em redes que não são suas (Wi-Fi do vizinho, do trabalho, da escola) é invasão — em vários países é crime, mesmo "só para testar". No Termux, use o nmap contra localhost, contra o seu próprio IP, ou em labs/CTFs autorizados. A aula Laboratório ético no próprio celular mostra o uso correto.

Túnel reverso: publique o site do celular com ngrok

O IP 192.168.1.42 só funciona dentro do Wi-Fi de casa. E se você quiser mostrar um site rodando no Termux para um amigo na internet? A solução preguiçosa (abrir porta no roteador, port forwarding) é perigosa e muitas vezes nem está disponível. A solução elegante é o túnel reverso: o celular abre uma conexão de saída para um servidor público (o do ngrok) e esse servidor entrega uma URL HTTPS que redireciona para o celular:

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
$ ngrok http 8080
Forwarding  https://termux-ana-7f3k.ngrok-free.app -> http://localhost:8080
Túnel aberto ✓ — seu site no celular está público na internet

Repare no desenho: ngrok http 8080 cria a URL https://termux-ana-7f3k.ngrok-free.app que aponta para a porta 8080 do próprio celular. O roteador não precisa de porta nenhuma aberta — a conexão é iniciada de dentro do celular para fora. É o mesmo truque usado para webhooks, bots e demos. O plano grátis do ngrok dá URL aleatória a cada sessão (dá para fixar com conta paga); o cloudflared (Cloudflare Tunnel) faz o mesmo de graça com URL fixa em conta paga.

ngrok
o cliente do serviço de túneis reversos (instale com pkg install ngrok)
http
o subcomando que cria um túnel para um servidor HTTP local
8080
a porta local do Termux que será exposta — a mesma do python -m http.server 8080
Túnel público = tudo o que está na porta fica público. Se você publisha a 8022 do SSH por engano, o mundo inteiro ganha uma porta de login no seu celular rootado. Publique somente a porta do site/serviço que você quer mostrar, desligue o túnel quando terminar (Ctrl+C no ngrok) e, no plano grátis, a URL é temporária — não conte com ela como endereço fixo.

localhost vs IP do Wi-Fi: por que os dois funcionam

Uma sutileza que confunde muita gente: no celular, localhost (127.0.0.1) e 192.168.1.42 parecem "o mesmo aparelho" — e são. A diferença é o caminho que o pacote faz:

  • localhost / 127.0.0.1: o pacote nem sai do celular; é o próprio sistema falando com ele mesmo. Por isso nmap localhost e ngrok http 8080 (que aponta para localhost:8080) funcionam até sem Wi-Fi ligado;
  • 192.168.1.42: o pacote vai até o roteador e volta — é o endereço que outros dispositivos da rede usam para falar com o seu celular (PC fazendo ssh ana@192.168.1.42 -p 8022).

O servidor do Termux precisa estar ouvindo em 0.0.0.0 (todas as interfaces) para aceitar conexões vindas do Wi-Fi — é o que o Serving HTTP on 0.0.0.0 port 8080 anuncia. Se um serviço só ouve em 127.0.0.1, ele responde para o próprio celular mas não para a rede.

Wi-Fi, dados móveis, VPN e proxy

O celular da Ana tem duas saídas para a internet, e o Termux usa a que estiver ativa:

  • Wi-Fi (wlan0): IP privado 192.168.1.42 atrás do roteador de casa — o SSH e o servidor web são alcançáveis pela rede local, e o ngrok publica para fora;
  • Dados móveis (rmnet0): IP dado pela operadora (geralmente atrás de CGNAT, sem IP público próprio) — acesso de fora precisa de túnel reverso ou VPN;
  • VPN: troca a "saída" da internet: com um app de VPN (WireGuard, por exemplo) o celular passa a aparecer em outra rede/IP, útil para acessar a rede de casa de fora com segurança — diferente de abrir porta no roteador, a VPN deixa o celular inside da rede;
  • Proxy: no Termux dá para rotear comandos por proxy com variáveis de ambiente (export http_proxy=http://...), útil em redes corporativas que exigem proxy.

Regra prática: em rede local, use o IP do Wi-Fi; fora de casa, use túnel reverso (ngrok/cloudflared) ou VPN — nunca port forwarding aberto na internet para um celular rootado.

Testando de verdade: curl no seu próprio servidor

Depois de subir o servidor web na 8080, confirme que ele responde de dentro do celular e pela rede local com o curl:

$ python -m http.server 8080 &
Serving HTTP on 0.0.0.0 port 8080 ...
$ curl -s http://localhost:8080 | head -3
<!doctype html>
<title>Directory listing for /</title>
$ curl -s http://192.168.1.42:8080 | head -3
<!doctype html>   # pelo IP do Wi-Fi também responde
$ curl -s https://termux-ana-7f3k.ngrok-free.app | head -3
<!doctype html>   # e pela URL pública do túnel

Três endereços, mesma página: localhost (só o celular), 192.168.1.42 (a rede local) e a URL do ngrok (a internet). Saber testar pelos três é o que separa "acho que funcionou" de "funcionou".

Pratique no celular da Ana

Missão: rode ifconfig e encontre o IP do celular na rede Wi-Fi: inet 192.168.1.42 na interface wlan0. Depois teste a internet com ping -c 1 8.8.8.8.

Missão: suba um servidor local com python -m http.server 8080 e abra o túnel reverso com ngrok http 8080. A URL pública https://termux-ana-7f3k.ngrok-free.app deve aparecer na saída. Também vale nmap localhost para ver 8022 e 8080 abertas.

Resumo

  • ifconfig mostra o IP do celular no Wi-Fi: wlan0 inet 192.168.1.42 (e lo = 127.0.0.1 = o próprio aparelho).
  • ping -c 1 8.8.8.8 confirma internet: 1 packets transmitted, 1 packets received.
  • nmap localhost lista as portas do próprio celular: 8022/tcp open ssh e 8080/tcp open http.
  • ngrok http 8080 cria túnel reverso: URL pública *.ngrok-free.app → porta 8080 do Termux, sem abrir porta no roteador.
  • Portas abertas em rede pública são porta de entrada — publique só o necessário e desligue o túnel ao terminar.
  • nmap só em redes próprias/autorizadas (veja Laboratório ético).
