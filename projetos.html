Projetos práticos no Termux — aprender fazendo

Até aqui você aprendeu as peças separadamente: pkg para instalar programas, termux-setup-storage para acessar as fotos, sshd para entrar no celular pelo PC, a Termux-API para câmera e GPS, termux-job-scheduler para agendar tarefas. Agora a Ana vai juntar tudo em projetos de verdade que rodam no próprio celular — um site público, um bot 24/7, sincronização com o PC e backup automático de fotos.

Você vai aprender
  • Como funcionam os projetos deste guia: cada um junta várias aulas em um passo a passo com arquivos completos e missões no terminal simulado ana@android.
  • Os pré-requisitos que todo projeto usa: pkg update, termux-setup-storage e o sshd na porta 8022 (aulas: pkg e apt, storage, sshd).
  • O roteiro de bolso de qualquer projeto no Termux: preparar → rodar → verificar → expor → automatizar.
  • Os cinco projetos: site externo com ngrok, bot de Telegram, sync com o PC via rsync e backup automático de fotos.

Como funcionam os projetos

Cada projeto é uma página curta e direta, com a mesma anatomia: um objetivo ("quero um site meu acessível de fora do Wi-Fi"), os passos numerados, os arquivos completos nas caixas de arquivo (pre.file, com botão de copiar), a saída real do terminal nas caixas pre.term e, no fim, as caixas Experimente você mesmo no terminal — o Termux simulado da máquina fictícia ana@android (um Pixel 7 Pro com Android 14, Termux instalado e um dispositivo rootado visível via adb). Nessas caixas há uma missão: digite o comando pedido e, quando a saída certa aparecer, você ganha o ✔ "Missão cumprida!". Se travar, use o botão Ver comando; para zerar a máquina, use Reiniciar.

Pré-requisitos: o que todo projeto precisa

Antes de qualquer projeto, a Ana deixa o celular pronto para trabalhar. São três coisas que aparecem em todos os projetos desta seção — e valem para o seu celular real também:

1. Pacotes atualizados e o programa certo instalado. O Termux usa o pkg (baseado no apt do Debian) em vez da Play Store — os pacotes são compilados para rodar no Android. O ritual é sempre pkg update antes de instalar qualquer coisa (veja pkg e apt):

$ pkg update
Get:1 https://packages.termux.dev/apt/termux-main stable InRelease
Reading package lists... Done
Building dependency tree... Done
$ pkg install python
The following NEW packages will be installed:
  python
0 upgraded, 1 newly installed, 0 to remove.
Setting up python (3.11.9-2) ...
python instalado ✓
pkg
o gerenciador de pacotes do Termux (o "apt do celular")
update
atualiza a lista de pacotes disponíveis nos repositórios
install python
baixa e instala o pacote python (e as dependências) direto do repositório do Termux

2. Acesso ao storage (fotos, downloads). Por padrão o Termux só enxerga a própria pasta privada. O comando termux-setup-storage cria links em ~/storage para a memória interna do celular — mas só depois de você aceitar a permissão que o Android mostra (veja storage). Sem isso, o ls ~/storage responde Permission denied:

$ ls ~/storage
ls: cannot access '/data/data/com.termux/files/home/storage': Permission denied
(dica: rode termux-setup-storage antes)
$ termux-setup-storage
Setting up storage access...
Links criados em ~/storage:
  dcim -> /storage/emulated/0/DCIM
  downloads -> /storage/emulated/0/Download
  pictures -> /storage/emulated/0/Pictures
  music -> /storage/emulated/0/Music
  movies -> /storage/emulated/0/Movies
  shared -> /storage/emulated/0
Storage configurado ✓ (aceite a permissão no Android)
$ ls ~/storage
dcim  downloads  movies  music  pictures  shared

3. O celular como servidor (SSH). Dois projetos precisam que o PC converse com o celular — e a ponte é o sshd rodando na porta 8022 (a 22 dá conflito; no Android sem root só dá para usar portas altas). O comando sshd sobe o servidor e já diz como conectar do PC (veja sshd no Termux):

$ sshd
Iniciando sshd na porta 8022...
sshd rodando ✓ — conecte do PC com:
  ssh ana@192.168.1.42 -p 8022
Permissão negada não é bug: se o ls ~/storage responder Permission denied, você pulou o termux-setup-storage ou negou a caixa de permissão do Android. Reabra o comando, aceite a permissão e tente de novo — sem isso nenhum projeto que mexe em fotos vai funcionar.

O roteiro de bolso de qualquer projeto

Repare no padrão: todos os projetos seguem o mesmo roteiro, e dá para decorar:

  • 1. Preparar — pkg update, instalar o que falta (pkg install python), dar acesso ao storage (termux-setup-storage).
  • 2. Escrever — criar os arquivos do projeto (index.html, bot.py, backup.sh) na pasta ~/projetos com o editor de sua escolha (veja vim, nano e VS Code).
  • 3. Rodar — subir o serviço no terminal (python -m http.server 8080, sshd, python bot.py).
  • 4. Verificar — confirmar que está no ar: ifconfig (qual o IP), nmap localhost (quais portas abertas), cat backup.log (o log fala).
  • 5. Expor — se precisar fora do Wi-Fi, túnel com ngrok; se precisar de outro dispositivo, sshd.
  • 6. Automatizar — agendar para rodar sozinho: termux-job-scheduler ou crontab (veja job-scheduler e crontab).

Todo projeto mora numa pasta própria dentro de ~/projetos, com o código e um arquivo de configuração fora do git:

projetos/
├── site/
│   └── index.html        # projeto 1: site estático
├── bot/
│   ├── bot.py            # projeto 2: bot de Telegram
│   └── config.env        # BOT_TOKEN=... (no .gitignore!)
└── backup.sh             # projeto 4: script de backup (na home: ~/backup.sh)
Projetos 24/7 consomem bateria: deixar um servidor ou bot rodando o dia inteiro no celular esquenta e gasta carga. Para isso existe o termux-wake-lock (veja wake lock) — e, no mundo real, prefira deixar o carregador conectado ou agendar as tarefas para horários em que o celular está na tomada.
Nunca exponha dados reais: os projetos deste guia usam a máquina fictícia ana@android de propósito. No seu celular real, não publique com ngrok pastas com fotos, documentos ou bancos de dados verdadeiros — o túnel deixa o conteúdo público na internet. Veja as regras em segurança no Termux e os erros comuns em problemas comuns.
