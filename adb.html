adb com root: o celular visto por fora

Até aqui você usou o Termux por dentro, como usuário comum (u0_a231). Mas o Pixel 7 Pro da Ana é rootado — e existe uma segunda porta para o sistema: o adb (Android Debug Bridge). Com ele, o PC enxerga o celular na USB/Wi-Fi, e com adb root o daemon do Android roda como root: adb shell whoami imprime root. Nesta aula você passa as três provas disso no terminal simulado.

Você vai aprender
  • O que é o adb e como o PC "enxerga" o celular (adb devices → serial R5CT20ABCPIXEL).
  • Que neste guia o aparelho é rootado: a saída traz Dispositivo rootado detectado ✓ (1 dispositivo).
  • adb root — o adbd passa a rodar como root: adbd is already running as root ✓.
  • adb shell whoami → root: dentro do shell do adb, você é o administrador do Android.
  • adb logcat — os logs do sistema, com root shell conectado no fim.
  • Outros comandos úteis: adb install, adb shell ls /data (acesso total a /data com root).
  • O risco: em produção o adbd não roda como root — root via adb é para labs e aparelhos de teste.

O que é o adb?

adb = Android Debug Bridge: um protocolo que deixa um computador falar com um aparelho Android — listar dispositivos, abrir um shell, instalar apps, ler logs. Ele tem três peças: o cliente (o comando adb no PC), o servidor (o processo adb em segundo plano no PC) e o daemon (adbd) rodando no próprio celular.

No Termux dá para rodar o cliente adb direto no celular apontando para outro aparelho (ou para si mesmo via Wi-Fi) — é o que o simulador faz aqui. No PC, você instala o platform-tools (pacote adb no Linux, "Android SDK Platform-Tools" no Windows/macOS).

$ adb devices        « no PC: quem está conectado?
List of devices attached
R5CT20ABCPIXEL	device product:blueline model:Pixel_7_Pro device:blueline

Missão 1: adb devices — o Pixel rootado aparece

O primeiro comando de qualquer sessão adb é ver quem está conectado:

Missão: digite adb devices e aperte Enter. Procure o serial R5CT20ABCPIXEL e a linha Dispositivo rootado detectado ✓ (1 dispositivo).

$ adb devices
List of devices attached
R5CT20ABCPIXEL	device product:blueline model:Pixel_7_Pro device:blueline

Dispositivo rootado detectado ✓ (1 dispositivo)
  • R5CT20ABCPIXEL — o serial do aparelho (cada Pixel tem um único);
  • device — o estado da conexão (pode ser unauthorized na primeira vez — aí você confirma o diálogo na tela do celular);
  • product:blueline model:Pixel_7_Pro — codinome e modelo: blueline é o Pixel 7 Pro.
adb
O cliente da ponte de debug.
devices
Subcomando que lista os aparelhos visíveis agora.
Se aparecer unauthorized: é o Android pedindo para o PC provar que pode falar com o aparelho. Olhe a tela do celular: aparece o diálogo "Permitir depuração USB deste computador?" — toque em Permitir (e marque "sempre permitir" se for seu PC). Sem isso, nenhum adb shell funciona.

Missão 2: adb root — o daemon vira root

Em celulares de produção (sem root), o adbd roda como usuário comum e adb root responde "cannot run as root in production builds". No Pixel rootado da Ana, não:

Missão: rode adb root. A saída deve trazer adbd is already running as root ✓ — o daemon do Android já está como root neste aparelho.

$ adb root
restarting adbd as root
adbd is already running as root ✓

A partir desse ponto, todo adb shell abre como root — o que muda tudo: dá para ler /data (a área privada de todos os apps, incluindo o próprio Termux), mudar configurações do sistema e instalar apps em modo silencioso.

Em produção isso não acontece: desde o Android 4.x, builds de fábrica vêm com ro.debuggable=0 e o adbd se recusa a virar root. O adb root só funciona em ROMs modificadas (root/Magisk com adb root habilitado) ou em emuladores com imagem "userdebug/eng" — como o Pixel da Ana neste guia. Trate como laboratório, nunca como estado normal de um aparelho de produção.

Missão 3: adb shell whoami — a prova: root

Agora abra um shell no celular pelo adb e pergunte quem você é:

Missão: rode adb shell whoami. A saída deve ser exatamente root — dentro do adb, você é o administrador do Android.

$ adb shell whoami
root
$ adb shell getprop ro.build.version.release
14
$ adb shell ls /data
« com root, a área privada de TODOS os apps está visível:
com.termux  com.android.chrome  com.whatsapp  ...

Compare com o Termux normal: lá dentro, whoami diz u0_a231 (ana) e /data nem aparece. Pelo adb com root, o sistema inteiro está aberto. Essa é a diferença entre "usuário do app" e "dono do sistema".

adb shell
Abre um shell no aparelho (não no PC) — é um terminal remoto dentro do Android.
whoami
O mesmo comando de sempre, só que agora no contexto do adbd: root.
getprop ro.build.version.release
Lê uma propriedade do sistema — aqui confirma o Android 14.

adb logcat: os logs do sistema

Outro comando clássico — o log em tempo real de tudo que acontece no Android:

$ adb logcat
--------- beginning of main
I/ActivityManager: Displayed com.termux/.app.TermuxActivity
D/adbd: root shell conectado

A última linha, D/adbd: root shell conectado, é a confirmação de que o daemon está em modo root. Para filtrar só erros: adb logcat *:E. Para parar: Ctrl+C.

Root via adb é para laboratório. Num celular de uso real, adbd como root só em ROM modificada — e isso anula várias proteções do Android (apps com root leem dados de todos os outros apps, incluindo senhas salvas). Neste guia o Pixel rootado serve para você ver a diferença; no dia a dia, fique no Termux como usuário comum.

adb por Wi-Fi, push/pull e outros úteis

Além do shell, o adb transfere arquivos nos dois sentidos e controla o aparelho:

$ adb connect 192.168.1.42:5555     « Android 11+: depuração sem fio
connected to 192.168.1.42:5555
$ adb push ~/backup.tar.gz /sdcard/Download/
~/backup.tar.gz: 1 file pushed. 2.3MB/s
$ adb pull /sdcard/Download/backup.tar.gz .
/sdcard/Download/backup.tar.gz: 1 file pulled.
$ adb reboot                              « reinicia o aparelho
$ adb shell dumpsys battery               « bateria vista pelo sistema (complementa o termux-battery-status)
adb connect IP:porta
Conecta no adbd por Wi-Fi (precisa ativar "Depuração sem fio" nas Opções do desenvolvedor).
adb push origem destino
Copia arquivo do PC para o celular.
adb pull origem destino
Copia arquivo do celular para o PC — ótimo para puxar fotos: adb pull /sdcard/DCIM/Camera .
adb shell dumpsys battery
Mostra a bateria em formato de sistema (a Termux-API usa o mesmo serviço por baixo).

Inspecionando o sistema por root: pm, dumpsys e getprop

Com o adbd como root, o shell do adb vira uma central de inspeção do Android:

$ adb shell pm list packages | grep termux
com.termux
com.termux.api
$ adb shell dumpsys battery | head -5
  AC powered: true
  level: 87
  status: Charging
$ adb shell getprop ro.product.model
Pixel 7 Pro
$ adb shell cat /data/data/com.termux/files/home/backup.log   « root lê a área privada do Termux
backup iniciado
backup concluido
  • pm list packages — todos os apps instalados (pm = package manager);
  • dumpsys battery — bateria em formato de sistema (o termux-battery-status usa esse serviço);
  • getprop — lê propriedades do sistema (modelo, versão, build);
  • cat /data/data/com.termux/… — com root, dá para ler a área privada do próprio Termux por fora.

Revogando o acesso depois do lab

Terminou o laboratório? Volte o adbd para o modo comum e limpe as autorizações no PC:

$ adb unroot            « adbd volta a rodar como usuário comum (em ROMs que permitem)
$ adb kill-server       « no PC: mata o servidor adb local
$ adb disconnect        « desconecta o Wi-Fi adb
« no celular: Opções do desenvolvedor → Revogar autorizações de depuração USB
Revogar depuração USB é o passo que todo mundo esquece: cada PC autorizado fica salvo no celular. Num aparelho rootado com adb root, qualquer máquina autorizada tem acesso de administrador. Depois de testar, revogue nas Opções do desenvolvedor e desligue a "Depuração USB" quando não estiver usando.

Resumo

  • O adb é a ponte PC ↔ Android: cliente no PC, daemon (adbd) no celular.
  • adb devices listou o R5CT20ABCPIXEL (Pixel 7 Pro) com Dispositivo rootado detectado ✓ (1 dispositivo).
  • adb root → adbd is already running as root ✓: neste aparelho rootado, o daemon já roda como root.
  • adb shell whoami → root: pelo adb, você é o administrador (diferente do u0_a231 (ana) do Termux).
  • adb logcat mostra os logs e termina com root shell conectado; adb install instala APKs.
  • Em produção o adbd não vira root — isso aqui é lab de aparelho rootado.
