Problemas comuns no Termux — FAQ de conserto

Todo mundo trava no Termux em alguma hora. A boa notícia: a mensagem de erro quase sempre diz o que fazer — e os problemas mais comuns são sempre os mesmos cinco ou seis. Esta página é o FAQ do guia, no formato sintoma → causa → solução, usando os erros reais da máquina da Ana (ana@android, Pixel 7 Pro com Android 14).

Você vai aprender
  • O app não abre / trava na tela preta: reinstalar pela F-Droid, limpar dados, permissão de armazenamento.
  • Permission denied no ~/storage: termux-setup-storage + aceitar a permissão no Android.
  • Unable to locate package: pkg update + nome certo via pkg search.
  • SSH recusado na 8022: sshd rodando, IP certo (ifconfig), mesma rede Wi-Fi, passwd/chaves.
  • Bateria drainando: termux-wake-unlock e cuidado com wake lock esquecido.
  • Termux-API muda: app Termux:API instalado e permissões concedidas.

O roteiro geral de diagnóstico

  1. Leia a mensagem inteira — no Termux ela costuma terminar com uma dica entre parênteses.
  2. Verifique o estado básico: pkg update em dia? termux-setup-storage feito? sshd no ar? IP atual com ifconfig?
  3. Reproduza no simulador abaixo: as missões provocam os erros de propósito para você treinar o reconhecimento.
  4. Se o app inteiro não abre, é caso de reinstalar (seção 1) — não de comando.

1. O app não abre (tela preta, fecha sozinho, trava no logo)

Sintoma real: o Termux abre e fecha na hora, ou fica numa tela preta piscando, ou "Termux parou". 
$ adb logcat
--------- beginning of main
I/ActivityManager: Displayed com.termux/.app.TermuxActivity
E/AndroidRuntime: FATAL EXCEPTION: main …

Causas comuns: (1) você instalou pela Play Store — a versão de lá está desatualizada e quebra em Android novos; (2) o cache/dados corromperam depois de uma atualização do Android; (3) falta a permissão de armazenamento nas configurações do app. Solução, nesta ordem:

  1. Desinstale e reinstale pela F-Droid (fdroid.org) — a fonte oficial e atualizada. Veja instalar certo.
  2. Se não quiser perder os arquivos: Ajustes → Apps → Termux → Armazenamento → Limpar cache (só o cache; "Limpar dados" apaga o home inteiro).
  3. Conceda a permissão de arquivos/mídia nas configurações do app Termux.
  4. Após reinstalar, rode pkg update && pkg upgrade para reconstruir o ambiente.

2. Storage negado — "Permission denied" no ~/storage

Erro real: 
$ ls ~/storage
ls: cannot access '/data/data/com.termux/files/home/storage': Permission denied
(dica: rode termux-setup-storage antes)

Causa: o Android isola cada app; o Termux só vê o próprio diretório até você autorizar o acesso às pastas compartilhadas (SAF). Solução: rode termux-setup-storage, aceite a caixa de diálogo do Android ("Permitir acesso a esta pasta") e teste:

$ termux-setup-storage
Storage configurado ✓ (aceite a permissão no Android)
$ ls ~/storage
dcim  downloads  movies  music  pictures  shared

As fotos do celular ficam em ~/storage/dcim (atalho para /storage/emulated/0/DCIM). Aula completa: termux-setup-storage. Erro detalhado em ref-erros.

3. O pacote não acha — "Unable to locate package"

Erro real: 
$ pkg install node
Unable to locate package node

Causa: no Termux o pacote chama-se nodejs, não node — e a lista de pacotes pode estar velha. Solução: atualize a lista e procure o nome certo antes de instalar:

$ pkg update
Reading package lists... Done
$ pkg search node
nodejs/stable 20.11.1 nodejs
$ pkg install nodejs
nodejs instalado ✓
$ node --version
v20.11.1

Se o pkg search responder No matches found, o programa pode não existir para Android no repositório Termux — procure alternativas (ex.: pkg search editor para achar vim/nano). Cola: ref-pkg.

4. SSH não conecta — "Connection refused" na 8022

Erro real (visto do PC): 
$ ssh ana@192.168.1.42 -p 8022
ssh: connect to host 192.168.1.42 port 8022: Connection refused

Causas, da mais comum para a menos comum: (1) o sshd não está rodando no Termux — ele não inicia sozinho; (2) o IP mudou (Wi-Fi reconectou e o DHCP deu outro número); (3) PC e celular em redes diferentes (2,4 GHz vs 5 GHz, ou dados móveis no meio); (4) firewall bloqueando a 8022. Solução, passo a passo:

$ sshd
Iniciando sshd na porta 8022...
sshd rodando ✓ — conecte do PC com:
  ssh ana@192.168.1.42 -p 8022
$ ifconfig
wlan0: …
        inet 192.168.1.42  netmask 255.255.255.0
$ ping -c 1 8.8.8.8
1 packets transmitted, 1 packets received, 0.0% packet loss ✓
  1. No celular: pkg install openssh (se ainda não tiver) e rode sshd.
  2. Confira o IP atual com ifconfig — anote o inet da wlan0.
  3. No PC, na mesma rede: ssh ana@IP -p 8022 (a porta do Termux é 8022, não 22).
  4. Se pedir senha e recusar: rode passwd no Termux para definir uma senha forte. Prefere chave? ssh-keygen no celular e copie a id_rsa.pub para o PC.
  5. Para o sshd subir sozinho no boot: termux-job-scheduler ou um script no ~/.bashrc — veja agendamento.

Aula completa: sshd no Termux. Depois de conectar, rode nmap localhost no celular para ver a porta aberta: 8022/tcp open ssh.

5. Bateria drainando — wake lock esquecido

Sintoma: o celular esquenta e a bateria cai em poucas horas mesmo "sem usar". Checando: 
$ termux-battery-status
{
  "level": 12,
  "status": "Discharging",
  "temperature": 41.0,
  …
}

Causa clássica: um script rodou termux-wake-lock para manter a tela ligada (ex.: servidor web ou backup de fotos) e nunca rodou termux-wake-unlock. A tela ligada é o maior consumidor de bateria do Android. Solução:

$ termux-wake-unlock
Wake lock liberado.
$ termux-wake-lock   « só durante o script, sempre com unlock no fim
Wake lock adquirido ✓ (a tela não apaga enquanto segurar)

Regra de ouro: todo termux-wake-lock precisa de um termux-wake-unlock no fim do script (use trap no bash para garantir mesmo se o script morrer no meio). Aula: Wake lock e termux-services.

6. Termux-API não responde (termux-*)

Se termux-battery-status responde command not found, faltou o pacote. Se responde permissão negada, faltou o app:

$ termux-battery-status
termux-battery-status: command not found (simulado — tente 'help')
$ pkg install termux-api
termux-api instalado ✓
$ termux-sms-list   « sem a permissão no app Termux:API → erro de permissão
$ termux-battery-status   « depois de liberar no app Termux:API:
{
  "level": 87,
  "status": "Charging",
  …
}

Solução: instale o pacote termux-api e o app Termux:API (F-Droid), abra o app e conceda cada permissão (SMS, localização, câmera, lanterna…). Cola completa: ref-termux.

7. Comando qualquer dá "command not found"

Typo é a causa nº 1; pacote não instalado é a nº 2. O próprio terminal te ajuda:

$ nmap localhost
nmap: command not found (simulado — tente 'help')
$ help
Termux simulado (ana@android):
  pkg update | pkg install python | pkg list-installed | pkg search vim
  termux-setup-storage   ls ~/storage
  …
$ pkg install nmap
nmap instalado ✓
$ nmap localhost
8022/tcp open  ssh
Nmap done: 1 IP address scanned ✓

Treine os consertos no terminal simulado

Missão 1 — consertar o storage: primeiro rode ls ~/storage e veja o Permission denied; depois rode termux-setup-storage (aceite a permissão) e rode ls ~/storage de novo — agora vem dcim downloads movies music pictures shared.

Missão 2 — subir o SSH: rode sshd e veja as instruções de conexão (ssh ana@192.168.1.42 -p 8022). Depois rode ifconfig para achar o IP e nmap localhost para confirmar a porta 8022 aberta.

Resumo

  • App não abre → reinstale pela F-Droid, limpe cache, dê permissão de arquivos; depois pkg update && pkg upgrade.
  • Permission denied no ~/storage → termux-setup-storage + "Permitir" na caixa do Android.
  • Unable to locate package → pkg update + pkg search para o nome exato.
  • SSH recusado na 8022 → sshd no celular, IP atual via ifconfig, mesma rede Wi-Fi, passwd/ssh-keygen.
  • Bateria drainando → procure termux-wake-lock ativo e rode termux-wake-unlock; cheque com termux-battery-status.
  • termux-* falhando → pacote termux-api + app Termux:API com permissões.
