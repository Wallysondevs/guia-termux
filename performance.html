Performance: o que o seu celular aguenta rodar

Um Pixel 7 Pro é um computador de bolso: Snapdragon 8 Gen 2, 8 GB de RAM e 128 GB de storage. Nesta aula você aprende a ler o hardware pelo terminal (termux-info), a monitorar processos em tempo real (htop), a entender a memória virtual do Android (zram/swap) e a usar um SSD ou pendrive via OTG para projetos pesados — tudo testado no terminal simulado ana@android.

Você vai aprender
  • Ler o hardware do celular com termux-info: CPU, RAM, storage, modelo e Android;
  • Monitorar CPU/RAM em tempo real com htop e interpretar 3.1/8 GB;
  • O que é zram (RAM comprimida) e quando o Android recorre a swap;
  • Expandir o storage com SSD/pendrive via cabo OTG e montar no Termux;
  • Manter o Termux rápido: pkg upgrade, limpeza de cache e processos travados;
  • Praticar no terminal simulado ana@android.

Conheça o hardware: termux-info

Antes de otimizar, meça. O termux-info imprime um resumo do aparelho e do ambiente Termux — no Pixel da Ana:

$ termux-info
TERMUX_VERSION=0.118.0
ANDROID_VERSION=14
CPU: Snapdragon 8 Gen 2
RAM total: 8 GB
Storage: 128 GB
Shell: /data/data/com.termux/files/usr/bin/bash
Device: Pixel 7 Pro (rooted)

Compare com um celular de entrada (2 GB de RAM): aí cada processo extra dói. Saber o hardware diz o que dá para rodar — no Pixel 7 Pro dá para segurar sshd + servidor web + banco de dados + um script de backup ao mesmo tempo sem drama.

Monitorando em tempo real: htop

O htop é o painel de controle vivo dos processos: barras de CPU por núcleo, uso de memória, swap e a lista de processos ordenada por consumo. Instale com pkg install htop e rode:

$ pkg install htop
...
htop instalado ✓
$ htop
CPU 12%  MEM 3.1/8 GB  SWAP 0
  1 root      Termux
  2 u0_a231   bash
(press q)
htop
o monitor interativo de processos (versão turbinada do top)
MEM 3.1/8 GB
3,1 GB de RAM em uso de 8 GB totais — sobra memória para mais serviços
SWAP 0
quanto da memória virtual (zram/disco) está em uso — zero é o ideal

Como ler: se a barra de MEM chega perto do total e o SWAP começa a crescer, o celular está "paginando" — trocando memória para o zram/disco, que deixa tudo lento. Nesse momento, feche apps ou mate processos pesados no próprio htop (tecla k mata o processo selecionado). No Termux, os vilões comuns são: vários python -m http.server esquecidos, sessões de proot-distro abertas, e o pkg upgrade rodando em paralelo com outra coisa.

Memória virtual no Android: zram e swap

O Android não usa swap em disco como um PC — ele usa zram: um bloco de RAM comprimida (geralmente metade da RAM física) que funciona como swap rápida. Quando a RAM enche, páginas pouco usadas são comprimidas para dentro do próprio chip — muito mais rápido que escrever em disco. No Pixel da Ana, com 8 GB, o zram costuma ser ~4 GB.

  • Vantagem: o celular aguenta mais apps abertos sem travar;
  • Desvantagem: zram consome CPU para comprimir/descomprimir — se o SWAP do htop está alto o tempo todo, há processo demais rodando;
  • Com root (Pixel rootado da Ana): dá para ajustar o tamanho do zram e o swappiness (tendência do kernel a usar swap) via /sys e /proc/sys/vm/swappiness — tuning fino para quem roda servidor 24/7 no celular.
Swap em SD/pendrive desgasta o cartão. Se for criar swap arquivo em armazenamento externo, use um SSD via OTG, não um microSD — ciclos de escrita constantes matam SD rapidamente. E nunca use swap como desculpa para rodar mais processos do que a RAM aguenta: o celular esquenta, a bateria drena e a experiência fica ruim.

Storage extra: SSD e pendrive via OTG

128 GB parecem muito até você encher com fotos, vídeos 4K e o bootstrap de três distros proot. A saída é um SSD/pendrive na porta USB-C com cabo OTG (o Pixel 7 Pro fala USB 3.2):

$ ls /dev/block/sda1
/dev/block/sda1
$ mkdir -p ~/ssd
$ mount /dev/block/sda1 ~/ssd        # com root/tsu
# ou, sem root, via SAF: termux-setup-storage já dá ~/storage
$ df -h ~/ssd
Filesystem      Size  Used Avail Use%  Mounted on
/dev/block/sda1 466G  120G  346G  26%  /data/data/com.termux/files/home/ssd

Sem root, o Termux acessa o armazenamento externo pelo ~/storage (após termux-setup-storage, aula storage); com root (ou tsu), dá para montar o SSD em qualquer pasta com mount. Usos práticos: clone de repositórios grandes, banco PostgreSQL com muitos dados (aula Bancos local), backups tar.gz das fotos, e o diretório de build de projetos pesados.

Medindo na prática: um mini benchmark no terminal

Quer saber se o celular está rápido hoje? Um teste rápido de escrita/leitura no storage interno diz mais que achismo. Rode no Termux:

$ time dd if=/dev/zero of=~/teste.bin bs=1M count=500 oflag=direct 2>&1 | tail -1
500+0 records in / 500+0 records out
real    0m 0.42s
$ rm ~/teste.bin
$ pkg install python
$ python --version
Python 3.11.9

O dd escreveu 500 MB no armazenamento interno e o time mediu o total: ~1,2 GB/s de escrita — é o UFS do Pixel 7 Pro falando. Se esse número cair muito (ex.: 50 MB/s), o armazenamento está cheio ou degradado — hora do pkg clean e de limpar fotos. Já o python --version mostra que a pilha de desenvolvimento também está rápida para rodar seus scripts.

Energia e temperatura: o freio invisível

Performance não é só GHz: é thermal throttling. O Snapdragon 8 Gen 2 esquenta (é um chip de notebook dentro de um celular) e, quando passa de ~40 °C no SoC, o Android reduz o clock para esfriar — e aí tudo fica lento de repente. Sinais de que isso está acontecendo: htop mostra CPU alta mas processos travados, o celular está quente na mão, a bateria drena rápido.

  • Não carregue o celular enquanto roda servidor/benchmark pesado — calor + carga = throttle;
  • Com root dá para ler a temperatura (cat /sys/class/thermal/thermal_zone0/temp) e o clock atual (cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq);
  • Para servidor 24/7 (ex.: o túnel ngrok), deixe o celular na sombra, com tela apagada (termux-wake-lock segura o processador, não a tela) e Wi-Fi ligado (dados móveis esquentam mais);
  • Se o aparelho estiver quente demais, pare os serviços pesados e deixe esfriar — forçar não adianta, o kernel manda.

Serviços no Termux: rode como daemon com tmux

Um erro comum: deixar o servidor aberto numa aba do terminal e fechar a aba sem querer — o processo morre junto. A solução é o tmux: ele cria sessões que continuam vivas mesmo se você fechar o Termux:

$ pkg install tmux
...
tmux instalado ✓
$ tmux new -s web
$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 ...
# aperta Ctrl+b e depois d: a sessão "web" continua rodando em background
$ tmux ls
web: 1 windows (created ...)
$ tmux attach -t web   # volta para a sessão quando quiser

Com isso dá para segurar vários serviços ao mesmo tempo — servidor web, sshd, túnel ngrok, script de backup — cada um numa sessão do tmux, todos sobrevivendo ao fechamento do app. É o jeito de transformar o celular num servidor de verdade.

Espaço em disco é performance

Storage cheio deixa o celular lento em tudo — o Android precisa de espaço livre para cache, zram e logs. No Termux, ache os culpados rapidinho:

$ du -sh ~/* 2>/dev/null | sort -rh | head -5
412M    projetos
180M    .cache
96M     storage
$ pkg clean
... limpando cache de pacotes baixados
$ df -h /data
Filesystem      Size  Used Avail Use%  Mounted on
/dev/block/dm-4  110G   78G   32G  71%  /data

Se o df -h /data mostra acima de ~85% usado, é hora de mover coisa para o SSD via OTG ou apagar downloads antigos. E rode pkg clean depois de grandes upgrades — o cache do pkg guarda os .deb baixados e pode comer gigabytes sem você perceber.

Pratique no Pixel da Ana

Missão: rode termux-info e confirme o hardware: CPU: Snapdragon 8 Gen 2, RAM total: 8 GB, Device: Pixel 7 Pro (rooted).

Missão: instale e rode o monitor: pkg install htop e depois htop. A linha MEM 3.1/8 GB mostra quanto de RAM está em uso. Apertar q no teclado real sai do htop.

Resumo

  • termux-info lê o hardware: Snapdragon 8 Gen 2, 8 GB RAM, 128 GB, Android 14, Pixel 7 Pro (rooted).
  • htop mostra CPU/MEM/SWAP em tempo real — 3.1/8 GB = 3,1 GB usados de 8 GB.
  • Android usa zram (RAM comprimida como swap rápida); swap alto = processos demais.
  • SSD/pendrive via OTG expande o storage; sem root use ~/storage, com root dá para mount em qualquer pasta.
  • Mantenha leve: pkg update && pkg upgrade, pkg clean, du -sh ~/* para achar o que ocupa espaço.
  • Antes de servidor longo: termux-wake-lock para a tela não apagar no meio.
