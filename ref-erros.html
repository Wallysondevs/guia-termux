Cola de erros comuns do Termux — mensagem → causa → solução

No Termux, ao contrário do Linux de PC, os erros mais comuns não são de código — são de permissão do Android e de nome de pacote. Quase sempre a mensagem já entrega a causa (e às vezes até a dica). Nesta página estão as trombadas que mais aparecem na máquina da Ana, cada uma com a mensagem real, a causa e o conserto na hora.

Você vai aprender
  • A ler um erro do Termux em 3 passos: qual comando falhou → qual a mensagem exata → a dica que vem junto.
  • Permission denied no ~/storage — faltou termux-setup-storage + aceitar a permissão no Android.
  • Unable to locate package X — nome errado ou falta pkg update.
  • command not found — o comando não existe (ou o pacote não foi instalado).
  • Conexão SSH recusada na porta 8022 — o sshd não está rodando no celular.
  • Permissão negada da Termux-API — liberar no app Termux:API.

Como ler um erro no terminal

ls ~/storage
o comando que você rodou
ls:
o programa que reclamou (quem emitiu o erro)
cannot access '…':
o que deu errado (não conseguiu acessar)
Permission denied
o motivo — permissão negada pelo Android/Termux

O padrão é sempre programa: o que deu errado: motivo. Quando o simulador imprime a dica embaixo (aquela linha com (dica: …)), é ela que resolve 90% dos casos.

1. Permission denied no ~/storage — o erro nº 1

$ ls ~/storage
ls: cannot access '/data/data/com.termux/files/home/storage': Permission denied
(dica: rode termux-setup-storage antes)

Causa: o Android isola os apps: o Termux só enxerga o próprio diretório privado (/data/data/com.termux/files) até você dar acesso ao resto. O termux-setup-storage cria os links em ~/storage e dispara a caixa de permissão do Android (SAF). Solução:

$ termux-setup-storage
Setting up storage access...
Links criados em ~/storage:
  dcim -> /storage/emulated/0/DCIM
  downloads -> /storage/emulated/0/Download
  …
Storage configurado ✓ (aceite a permissão no Android)
$ ls ~/storage
dcim  downloads  movies  music  pictures  shared
Se mesmo depois do setup ainda der Permission denied: abra o app de arquivos do Android, vá em ~/storage pelo Termux, e na caixa de diálogo do sistema toque em "Permitir"/"Usar esta pasta" — o Android sometimes pede de novo depois de atualizar o app.

2. Unable to locate package — o erro nº 2 do pkg

$ pkg install node
Unable to locate package node
$ pkg search node
nodejs/stable 20.11.1 nodejs
$ pkg install nodejs
Setting up nodejs (20.11.1) ...
nodejs instalado ✓
$ node --version
v20.11.1

Causa: o nome não existe no repositório Termux — no exemplo, o certo é nodejs, não node. A segunda causa é lista velha: rode pkg update primeiro. Solução: procure antes (pkg search) e instale pelo nome exato.

3. command not found — digitou errado ou não instalou

$ nmap localhost
nmap: command not found (simulado — tente 'help')
$ pkg install nmap
Setting up nmap (7.94) ...
nmap instalado ✓
$ nmap localhost
Starting Nmap 7.94 (simulado)
Host 192.168.1.42 is up.
PORT     STATE SERVICE
8022/tcp open  ssh
8080/tcp open  http
Nmap done: 1 IP address scanned ✓

Causa: ou é erro de digitação, ou o pacote que traz o comando ainda não foi instalado. O próprio simulador sugere help, que lista tudo o que existe na máquina da Ana. Solução: help para ver o que está disponível; pkg install … para instalar o que falta.

4. SSH recusado na 8022 — o sshd não está no ar

Do lado do PC, quando o celular não está ouvindo, o erro aparece assim:

$ ssh ana@192.168.1.42 -p 8022
ssh: connect to host 192.168.1.42 port 8022: Connection refused

Causa: o sshd não está rodando no Termux (o Termux não inicia o servidor sozinho no boot, a menos que você configure), ou o IP/porta estão errados, ou o PC e o celular estão em redes diferentes. Solução, no celular:

$ sshd
Iniciando sshd na porta 8022...
sshd rodando ✓ — conecte do PC com:
  ssh ana@192.168.1.42 -p 8022
$ ifconfig
wlan0: …
        inet 192.168.1.42  netmask 255.255.255.0

A porta padrão do Termux é a 8022 (a 22 precisa de root). Sempre confira o IP atual com ifconfig — no Wi-Fi ele muda quando reconecta. Detalhes na aula sshd no Termux e no FAQ de problemas comuns.

5. Permissão da Termux-API negada

Comandos termux-* falham de formas diferentes: ou command not found (pacote termux-api não instalado) ou permissão negada pelo Android (app Termux:API sem a permissão). A causa é sempre a mesma: instale o pacote e o app, e conceda a permissão:

$ pkg install termux-api
termux-api instalado ✓
$ termux-sms-list   « depois de liberar SMS no app Termux:API
[{"number":"+5511999887766","body":"Seu código é 123456"},…]

6. Erros de rede: ping, ifconfig e nmap

Quando o problema é a conexão (SSH recusado, ngrok não abre, PC não acha o celular), os três comandos abaixo diagnosticam:

$ ping -c 1 8.8.8.8
PING 8.8.8.8: 56 data bytes
64 bytes: icmp_seq=0 ttl=117 time=23.4 ms
1 packets transmitted, 1 packets received, 0.0% packet loss ✓
$ ifconfig
wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>
        inet 192.168.1.42  netmask 255.255.255.0
$ nmap localhost
PORT     STATE SERVICE
8022/tcp open  ssh
8080/tcp open  http
Nmap done: 1 IP address scanned ✓

Se o ping falha, é DNS/conectividade; se o IP do ifconfig mudou, o endereço antigo do ssh está errado; se o nmap localhost não mostra a porta, o servidor (sshd/http) não está rodando. Cada erro desse trio tem a causa obvious depois de medir.

Checklist antes de chamar de "bug"

  1. pkg update está em dia? (resolve Unable to locate package)
  2. termux-setup-storage foi rodado e a permissão aceita? (resolve Permission denied no storage)
  3. O pacote do comando foi instalado? pkg list-installed lista; help mostra os comandos vivos.
  4. O serviço está no ar? sshd, python -m http.server, nginx — nmap localhost confirma as portas.
  5. O IP/porta estão certos? ifconfig no celular, -p 8022 no ssh.
  6. O app Termux:API tem as permissões? (resolve falhas de termux-sms-list, termux-location…)

Provoque os erros no simulador (treino de reconhecimento)

Missão 1 — Permission denied: rode ls ~/storage antes de configurar o storage e veja o erro completo. Depois rode termux-setup-storage e tente de novo — agora a lista aparece.

Missão 2 — pacote fantasma: rode pkg install abacate para ver Unable to locate package abacate. Depois rode pkg search vim e um comando inexistente tipo abacate para ver o command not found.

Resumo

  • Leia o erro no padrão programa: problema: motivo — e siga a dica impressa embaixo quando houver.
  • Permission denied no ~/storage → termux-setup-storage + aceitar no Android.
  • Unable to locate package X → pkg update + nome certo via pkg search (ex.: nodejs, não node).
  • command not found → help lista os comandos; instale o pacote que falta.
  • SSH recusado na 8022 → rode sshd no celular e confira o IP com ifconfig.
  • Termux-API negada → app Termux:API com as permissões liberadas.
