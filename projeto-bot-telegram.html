Projeto 2 — bot de Telegram rodando no Termux 24/7

No projeto anterior o servidor parava quando o terminal fechava. Agora a Ana quer o contrário: um processo que nunca morre. Ela vai criar um bot de Telegram em Python que responde comandos no chat — e deixar esse bot rodando o dia inteiro no celular, mesmo com a tela apagada. Para isso ela junta três peças: o interpretador Python, uma sessão tmux que sobrevive ao app fechado e o termux-wake-lock que impede o Android de dormir.

Você vai aprender
  • A instalar o Python no Termux com pkg install python e conferir com python --version.
  • A criar um bot no BotFather (o bot oficial do Telegram) e receber o token — a "senha" do bot.
  • A escrever o bot.py com a biblioteca python-telegram-bot e rodar com python bot.py.
  • A deixar o bot no ar de verdade: sessão tmux + termux-wake-lock (aulas: wake lock, editores).
  • Os riscos reais: token vazando no código, bateria 24/7 e o que acontece quando o Android mata o app.

Passo 1 — instalar o Python

O bot é um programa Python, então o primeiro passo é garantir o interpretador no celular. A Ana já fez pkg update nos pré-requisitos (veja projetos e pkg e apt) e agora instala:

$ pkg install python

python instalado ✓
$ python --version
Python 3.11.9

Missão: instale o Python no simulador: digite pkg install python — a última linha da saída é python instalado ✓. Depois confirme com python --version (mostra Python 3.11.9).

pkg install
o gerenciador de pacotes do Termux baixa o pacote do repositório oficial e instala
python
o nome do pacote — o Termux compila tudo para a arquitetura do celular (aarch64)
python --version
sempre confirme a instalação perguntando a versão ao próprio programa

Com o Python no lugar, a Ana instala a biblioteca do bot com o pip (que vem junto): pip install python-telegram-bot. No simulador isso não existe, mas no celular real é esse o comando — e o pip é o gerenciador de pacotes do Python, análogo ao pkg do Termux.

Passo 2 — criar o bot no BotFather e pegar o token

Todo bot de Telegram nasce no @BotFather, o bot oficial do próprio Telegram. Pelo app do Telegram (celular ou PC), a Ana manda:

$ # no Telegram, fale com o @BotFather:
# /newbot -> escolhe o nome (Ana Helpdesk Bot) e o @usuario (ana_helpdesk_bot)
# o BotFather responde com o TOKEN:
# 7315204186:AAH1x...  (use esse token no seu bot.py — NUNCA compartilhe)

Esse token é a senha mestra do bot: quem tem o token controla o bot — manda mensagem por ele, lê as conversas, apaga o bot. Por isso a regra número 1 de bots: nunca coloque o token direto no código que vai para o GitHub. O jeito certo é ler de uma variável de ambiente ou de um arquivo fora do repositório:

# ~/projetos/bot/config.env  (adicione ao .gitignore!)
BOT_TOKEN=7315204186:AAH1x...(token que o BotFather deu)
Token no código = bot roubado: se você commitar o BOT_TOKEN num repositório público, em minutos um robô varre o GitHub, pega seu token e usa seu bot para spam — e a conta do Telegram pode ser banida. Sempre: .gitignore com config.env, token em variável de ambiente (os.environ["BOT_TOKEN"]), e se vazar, revogue no próprio @BotFather com /revoke e gere um novo.

Passo 3 — escrever o bot.py

Com o token em mãos, a Ana escreve o bot na pasta ~/projetos/bot. Um bot mínimo que responde /start e ecoa o resto (com a biblioteca python-telegram-bot, a API de bots do Telegram em Python):

#!/data/data/com.termux/files/usr/bin/python3
# bot.py — bot de Telegram rodando no Termux (ana@android)
import os
from telegram import Update
from telegram.ext import ApplicationBuilder, CommandHandler, MessageHandler, ContextTypes, filters

TOKEN = os.environ.get("BOT_TOKEN")  # NUNCA hardcode o token aqui!

async def start(update: Update, context: ContextTypes.DEFAULT_TYPE):
    await update.message.reply_text(
        "Oi! Eu sou o bot da Ana e estou rodando 24/7 no Termux 📱\n"
        "Comandos: /start /status /ajuda"
    )

async def status(update: Update, context: ContextTypes.DEFAULT_TYPE):
    await update.message.reply_text("Status: online ✓ (celular: Pixel 7 Pro, Android 14)")

async def eco(update: Update, context: ContextTypes.DEFAULT_TYPE):
    await update.message.reply_text(f"Você disse: {update.message.text}")

app = ApplicationBuilder().token(TOKEN).build()
app.add_handler(CommandHandler("start", start))
app.add_handler(CommandHandler("status", status))
app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, eco))

print("Bot rodando... (Ctrl+C para parar)")
app.run_polling()  # fica perguntando ao Telegram se chegou mensagem nova

Os pontos importantes desse código: o token vem de os.environ (carregado do config.env antes de rodar: source ~/projetos/bot/config.env), e o app.run_polling() é o loop infinito que mantém o bot vivo perguntando ao Telegram "chegou mensagem?" a cada poucos segundos. Enquanto esse loop roda, o bot responde.

$ source ~/projetos/bot/config.env
$ python ~/projetos/bot/bot.py
Bot rodando... (Ctrl+C para parar)
# no Telegram, a Ana manda /start no @ana_helpdesk_bot e o bot responde na hora

Passo 4 — deixar o bot no ar 24/7: tmux + wake lock

Se a Ana rodar python bot.py direto no Termux e fechar o app, o Android mata o processo na hora. Para o bot ficar no ar de verdade, ela usa duas ferramentas:

1. O tmux — um "multiplexador de terminal": cada sessão do tmux roda independente do app estar aberto na tela. A Ana instala (pkg install tmux), entra (tmux), roda o bot dentro da sessão e destaca com Ctrl+B e depois D — o bot continua rodando "por trás". Depois é só tmux attach para voltar a ver:

$ pkg install tmux
...
tmux instalado ✓
$ tmux new -s bot        # cria a sessão "bot"
# dentro da sessão:
$ source ~/projetos/bot/config.env && python ~/projetos/bot/bot.py
Bot rodando... (Ctrl+C para parar)
# Ctrl+B depois D para destacar — o bot continua vivo
$ tmux ls
bot: 1 windows (created ...)
$ tmux attach -t bot    # volta para ver o bot

2. O wake lock — o Android apaga a tela e suspende os apps depois de um tempo; o termux-wake-lock diz ao sistema "não durma enquanto eu estiver segurando esse lock" (veja wake lock e termux-services). A Ana segura o lock dentro da sessão do bot:

$ termux-wake-lock
Wake lock adquirido ✓ (a tela não apaga enquanto segurar)
termux-wake-lock
adquire um "wake lock" parcial: a CPU continua ligada e o app não é suspenso, mesmo com a tela apagada
tmux new -s bot
cria uma sessão nova chamada bot — o nome serve para voltar nela depois (tmux attach -t bot)
Ctrl+B, D
"detach": sai da sessão sem matar o que está rodando nela — é o truque que faz o bot sobreviver ao app fechado

Missão: segure o celular acordado no simulador: digite termux-wake-lock — a saída confirma Wake lock adquirido ✓.

24/7 no celular tem preço: tela ligada + CPU ativa + rádio do Telegram polling gastam bateria — confira com termux-battery-status. No mundo real, deixe o celular na tomada (ou agende o bot para ligar só de dia, com o termux-job-scheduler). E lembre: o Android pode matar apps em segundo plano mesmo com wake lock em celulares agressivos — para serviços realmente críticos, o caminho é o termux-services com sv ou um servidorzinho de verdade (VPS).
$ termux-battery-status
{
  "level": 87,
  "status": "Charging",
  "temperature": 31.5,
  "plugged": "AC",
  "health": "Good"
}

Passo 5 — conferindo se o bot está vivo

Bot no ar não é bot respondendo. A Ana confere de tempos em tempos: manda /status no Telegram, olha o log da sessão do tmux (tmux attach -t bot) e, no próprio celular, confirma que o processo Python está na lista:

$ htop

Bot de Telegram no Termux é para aprender e para uso pessoal: o plano gratuito do Telegram não foi feito para bots comerciais em celular — para produção use um servidor (VPS) com systemd, e ative a 2FA na conta. E nunca peça dados sensíveis (senhas, códigos de banco) por um bot que você não controla 100%.

Extra — editando o bot de longe e reiniciando sozinho

Com o bot no ar, a Ana percebe que editar o bot.py no teclado virtual do celular é chato. A solução é o que ela vai montar no próximo projeto: o sshd no celular, para editar os arquivos do PC por SSH/SCP (sync celular ↔ PC). E para o bot voltar sozinho depois que o celular reiniciar, dá para registrar um script de boot no Termux (~/.termux/boot/, que roda quando o app abre) — no simulador, o análogo é agendar com o termux-job-scheduler (veja job-scheduler e crontab):

$ termux-job-scheduler --script ~/projetos/bot/start.sh --period 3600000
Job agendado (id 1): ~/projetos/bot/start.sh a cada 3600000 ms ✓
#!/data/data/com.termux/files/usr/bin/bash
# start.sh — garante que o bot está no ar (roda dentro do tmux)
if ! tmux has-session -t bot 2>/dev/null; then
  tmux new -d -s bot
  tmux send-keys -t bot "source ~/projetos/bot/config.env && python ~/projetos/bot/bot.py" Enter
fi
termux-wake-lock

O start.sh é idempotente: se a sessão bot já existe, não faz nada; se não existe, cria e manda o comando de subir o bot. Esse padrão — "garanta que o estado desejado existe" — é o mesmo que o Kubernetes usa com seus controladores, e dá para aplicar em qualquer script de automação no Termux.

Fluxo de trabalho recomendado: desenvolva o bot no PC (VS Code + Python), mande para o celular com rsync/scp pela porta 8022, e só rode python bot.py no Termux dentro do tmux. Editar código no celular é para emergência — o teclado virtual não perdoa.

Resumo

  • Bot de Telegram = programa Python que fica num loop (app.run_polling()) perguntando ao Telegram se chegou mensagem.
  • Instale a base com pkg install python (python instalado ✓, Python 3.11.9) e a biblioteca com pip install python-telegram-bot.
  • O token vem do @BotFather e é a senha do bot: guarde em config.env fora do git (com .gitignore) e leia com os.environ — nunca no código.
  • Para rodar 24/7: sessão tmux (tmux new -s bot, destaque com Ctrl+B,D) + termux-wake-lock (Wake lock adquirido ✓).
  • Verifique que está vivo: tmux ls, tmux attach -t bot, /status no Telegram, htop/ps no celular e termux-battery-status para a bateria.
  • Bateria é o limite real do 24/7 no celular: carregador ligado ou agendamento com termux-job-scheduler.
