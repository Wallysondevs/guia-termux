Editores no celular: vim, nano e VS Code no Termux

Você já escreveu scripts como o ~/backup.sh — mas no celular, editar com o quê? Nesta aula você instala os dois editores de terminal clássicos (vim e nano) com o pkg e aprende os comandos mínimos para não travar neles, além de conhecer as opções gráficas para editar com conforto: o code-server (VS Code rodando no próprio celular, aberto no navegador) e o app Acode.

Você vai aprender
  • Instalar editores: pkg install vim nano;
  • Abrir e sair do vim sem travar: i, Esc, :w, :q, :wq, :q!;
  • O nano, mais amigável: Ctrl+O salva, Ctrl+X sai;
  • Editar o ~/backup.sh e criar notas.txt no terminal;
  • VS Code no celular: code-server no navegador via localhost + o app Acode.

Instalando os editores

Tudo começa com o pkg. Vim e nano são pacotes pequenos e já vêm prontos para Android:

$ pkg install vim nano
The following NEW packages will be installed:
  vim nano
...
vim instalado ✓
nano instalado ✓
$ pkg search vim
nano/stable 7.2 nano
vim/stable 9.1.0 vim
...

O pkg search vim mostra os pacotes que têm "vim" no nome — dá para usar para descobrir variantes (ex.: vim-python).

vim: o editor que todo servidor tem

O vim é o editor padrão de praticamente todo Linux — incluindo servidores que você acessa por SSH. No celular ele é essencial porque é leve e já vem em quase todo lugar. Abrindo um arquivo:

$ vim notas.txt
(simulado) editor vim aberto — :q para sair 😄

O grande drama do vim é sair dele. A regra de ouro: o vim tem "modos". Ele abre no modo normal (onde teclas são comandos), e para escrever você entra no modo de inserção:

Tecla/comandoModoO que faz
inormal → inserçãoentra no modo de escrita (antes do cursor)
Escvolta ao normalsai do modo de escrita — sempre aperte Esc antes de salvar/sair
:w + Enternormalsalva o arquivo (write)
:q + Enternormalsai (quit) — só funciona se não houver alterações não salvas
:wq + Enternormalsalva e sai de uma vez
:q! + Enternormalsai sem salvar (o "!" força) — cuidado!
dd / yy / pnormalapaga linha / copia linha / cola
unormaldesfaz (undo)
O clássico "não consigo sair do vim": se você digitou texto e tenta :q, o vim reclama (E37: No write since last change) porque tem alterações não salvas. A sequência de fuga é: Esc → :q! → Enter (sai sem salvar) ou Esc → :wq → Enter (salva e sai). No simulador, o vim abre e fecha com :q direto, mas num celular real essa tabela vale ouro.

nano: o editor amigável

Se o vim intimida, o nano é o oposto: as teclas ficam escritas no rodapé da tela (^O Write Out, ^X Exit) e o Ctrl no terminal do celular é o botão Ctrl do Termux (ou o atalho de teclado Bluetooth):

$ nano notas.txt
(simulado) editor nano aberto — :q para sair 😄
AtalhoSignificadoO que faz
Ctrl+O + EnterWrite Outsalva o arquivo (pede confermação do nome)
Ctrl+XExitsai — se houver alteração não salva, pergunta se quer salvar
Ctrl+KCutrecorta a linha inteira
Ctrl+UUncutcola o que foi recortado
Ctrl+WSearchprocura um texto no arquivo

Para o dia a dia no celular, o nano é o suficiente: abrir, editar o backup.sh, salvar, sair. Guarde o vim para quando você precisar dele num servidor remoto (a quase todo VPS tem vim e nem sempre tem nano).

Editando seus scripts no terminal

Editar no celular não é só para notas — é para ajustar os scripts de automação que vimos (job-scheduler, wake lock). O fluxo típico da Ana: abrir o script, mudar uma linha, salvar, deixar o cron fazer o resto:

$ vim backup.sh
(simulado) editor vim aberto — :q para sair 😄
$ cat backup.sh
#!/data/data/com.termux/files/usr/bin/bash
echo "backup iniciado"
tar -czf ~/backup.tar.gz ~/storage/shared/DCIM
echo "backup concluido"
$ crontab -l
# crontab do Termux (ana@android)
*/30 * * * * ~/backup.sh >> ~/backup.log 2>&1

Repare que o crontab -l continua apontando para o ~/backup.sh — ou seja, qualquer mudança que você salvar no editor vale na próxima execução automática, sem reiniciar nada.

VS Code no celular: code-server e Acode

Terminal é bom, mas às vezes você quer editor com sintaxe colorida, autocompletar e interface gráfica. Duas opções populares no Termux:

  • code-server (VS Code rodando como servidor): instale com npm install -g code-server (depois de pkg install nodejs), rode code-server --port 8080 e abra http://localhost:8080 no navegador do próprio celular — você terá o VS Code inteiro, com acesso aos arquivos do Termux. Combine com o wake lock para editar de madrugada sem a tela apagar.
  • Acode: um app editor de código para Android (instale pela F-Droid) com plugin que abre um terminal Termux embutido — você edita o arquivo com interface gráfica e roda os comandos no terminal de baixo.
$ pkg install nodejs
...
nodejs instalado ✓
$ node --version
v20.11.1
$ npm install -g code-server   # no Termux real
$ code-server --port 8080      # abre o VS Code em http://localhost:8080
code-server pede senha: por padrão ele gera uma senha e mostra no terminal (ou em ~/.config/code-server/config.yaml) — anote antes de abrir no navegador. E rodando só em localhost, ele não fica exposto na internet; se for expor fora de casa, use túnel (ngrok) com senha forte.

Missões no simulador

Na máquina ana@android, abra os dois editores:

Missão: abra o vim com vim notas.txt — a saída mostra (simulado) editor vim aberto — :q para sair 😄.

Missão: agora abra o nano com nano notas.txt — a saída mostra editor nano aberto. Depois instale os dois de verdade no simulador: pkg install vim nano.

Teclado no celular: onde fica o Ctrl e o Esc?

Editor de terminal no celular vive ou morre pelos atalhos de teclado. No Termux, a barra de teclas extras (acima do teclado virtual) traz Esc, Ctrl, Alt, setas e :w — deslize essa barra ou segure Vol+ para ver as teclas extras. Atalhos úteis:

AtalhoEquivalenteUso
Vol+ ( segura )abre a barra de teclas extrasacessar Esc, Ctrl, setas, |, ~
Vol- + teclaCtrl + teclano nano: Ctrl+O salva; no vim: combinações de comando
teclado Bluetoothteclado de PCpara editar a sério, um teclado dobrável + celular é um setup adorável
tap longo no botão do Termuxmenu de contextocolar texto, abrir nova sessão, acessar configurações

Versionando suas notas e scripts com git

Depois de editar bastante, você vai querer histórico ("quem apagou aquela linha do backup.sh?"). O git funciona normal no Termux:

$ pkg install git
...
git instalado ✓
$ cd ~/projetos
$ git init
Initialized empty Git repository in /data/data/com.termux/files/home/projetos/.git/
$ git add backup.sh
$ git commit -m "backup da DCIM a cada 30 min"
[main (root-commit) abc1234] backup da DCIM a cada 30 min

Com isso, cada alteração no script editado no vim/nano fica registrada — e dá para sincronizar com um repositório remoto (GitHub) ou com o PC via rsync/ssh. Editar + versionar no próprio celular fecha o ciclo: o Termux vira uma máquina de desenvolvimento completa, não só um terminal.

vim ou nano: qual escolher?

vimnano
Curva de aprendizadoíngreme (modos!) — mas vale cada minutoplana: os atalhos estão na tela
Onde você encontraem todo servidor Linux (SSH remoto)na maioria, mas nem sempre
Potênciaedição programável, macros, splitsedição direta, suficiente pro dia a dia
Para o celularmelhor com teclado Bluetoothmelhor com teclado virtual + barra extra
Regra práticaaprenda o básico (tabela acima) e use quando precisaruse para editar scripts rápidos no celular
Erros reais ao editar no celular: (1) arquivo "somente leitura" — cheque as permissões (ls -l); (2) salvar em cima de arquivo do sistema dá erro — edite só dentro de ~; (3) no vim, apertar teclas no modo normal "bagunça" o texto — Esc + u (undo) salva; (4) teclado virtual cobrindo a linha de comando do editor — use a barra de teclas extras do Termux ou um teclado Bluetooth.

Anatomia do vim: os dois modos

O conceito que destrava o vim é que ele tem dois modos e você alterna entre eles:

modo normal
teclas são comandos (dd apaga, yy copia, :w salva). É o modo inicial.
modo de inserção
teclas escrevem texto de verdade — entra com i (ou a), sai com Esc.
linha de comando
começa com : no modo normal — :w (salva), :q (sai), :wq (salva e sai), :q! (sai sem salvar).

A regra de ouro para nunca travar: Esc antes de qualquer coisa — se você não sabe em que modo está, aperte Esc (voltar ao normal nunca estraga nada) e aí rode :wq ou :q!.

Criando um script do zero no celular

O fluxo completo que você vai viver: abrir o editor, escrever o script, salvar, dar permissão de execução e rodar — tudo pelo terminal do celular:

#!/data/data/com.termux/files/usr/bin/bash
echo "meu primeiro script no Termux"
termux-toast "rodei pelo terminal ✓"
date
$ nano ~/meu-primeiro-script.sh
(simulado) editor nano aberto — :q para sair 😄
$ chmod +x ~/meu-primeiro-script.sh
$ ~/meu-primeiro-script.sh
(simulado) script rodaria aqui — no celular real, a saída apareceria na hora
$ crontab -l   # e dá para agendar!
# crontab do Termux (ana@android)
*/30 * * * * ~/backup.sh >> ~/backup.log 2>&1

Esse é o ciclo de vida de um script no Termux: editar → salvar → executar → agendar. Com vim ou nano no terminal, code-server no navegador ou Acode com interface gráfica, o celular deixa de ser só um consumidor de conteúdo e vira uma máquina de criar.

Resumo

  • pkg install vim nano instala os dois editores de terminal no Termux.
  • vim: i entra no modo de escrita, Esc volta, :w salva, :q sai, :wq salva e sai, :q! sai sem salvar.
  • nano: Ctrl+O salva, Ctrl+X sai — mais amigável para começar.
  • Edite scripts como o ~/backup.sh direto no terminal; o crontab já usa a versão salva na próxima execução.
  • VS Code no celular: code-server via npm, abrindo http://localhost:8080 no navegador; ou o app Acode com terminal embutido.
  • O vim é obrigatória para servidores remotos — vale decorar a tabela de teclas.
