Glossário de Termux, de A a Z

Todo guia de Termux usa os mesmos termos o tempo inteiro — e eles voltam em todo canto: no pkg, nos erros, nas aulas de root. Este glossário reúne os termos essenciais em ordem alfabética, com definição em português claro e o comando de exemplo na máquina da Ana (ana@android, Pixel 7 Pro com Android 14). Consulte sempre que um termo novo aparecer.

Você vai aprender
  • O ambiente: Termux, $PREFIX, bootstrap, app uid (u0_a231).
  • Pacotes: pkg/apt, repositório termux-main, F-Droid.
  • Controle do celular: Termux-API, termux-setup-storage, ~/storage, SAF.
  • Root e acesso remoto: adb, root/su, sshd (porta 8022).
  • Linux dentro do Linux e rede: proot/proot-distro, ngrok, wake lock, crontab/termux-job-scheduler.

Os termos, de A a Z

adb (Android Debug Bridge)
A ponte de depuração do Android: com ela você lista dispositivos (adb devices), abre shell no celular (adb shell whoami), lê logs (adb logcat), instala APKs (adb install app.apk) e, num aparelho rootado, vira root (adb root). No guia, o Pixel 7 Pro da Ana responde R5CT20ABCPIXEL e está rootado. Cola em ref-adb.
Android / SAF
O sistema operacional do celular. O SAF (Storage Access Framework) é o mecanismo de permissão de pastas do Android 5+: cada app só enxerga os próprios arquivos até o usuário "aceitar" uma pasta na caixa de diálogo — é por isso que o ~/storage precisa do termux-setup-storage.
App uid — u0_a231
Cada app Android roda com um usuário Linux próprio: o Termux da Ana é o u0_a231 (o comando whoami dentro do Termux imprime u0_a231 (ana)). O número depois do u0_ é o "user id" do app — cada app instalado ganha um diferente. É por isso que o Termux não pode ler os arquivos de outros apps sem permissão.
Bootstrap
O "pacote inicial" que o Termux baixa na primeira execução (ou no proot-distro install): o conjunto mínimo de binários (bash, coreutils, pkg…) compilados para Android que permite o resto instalar. Sem bootstrap não existe Termux.
crontab / termux-job-scheduler
As duas formas de agendar tarefas no Termux: o crontab -l lista ("*/30 * * * * ~/backup.sh …") e o termux-job-scheduler --script ~/backup.sh --period 300000 agenda pelo sistema do Android (sobrevive a reinícios do app). Aula termux-job-scheduler e crontab.
F-Droid
A loja de apps open source recomendada para instalar o Termux e o Termux:API. A versão da Play Store está desatualizada (o Google Play restringe atualizações de apps que mexem em pacotes) — por isso a regra de ouro: instale pelo F-Droid. Aula instalar certo.
ngrok
Serviço de túnel reverso: expõe um servidor local (ex.: python -m http.server 8080 no celular) num endereço público HTTPS (https://termux-ana-7f3k.ngrok-free.app). Perfeito para mostrar um site rodando no Termux para alguém de fora. Aula Rede no celular e projeto site externo.
pkg / apt
O gerenciador de pacotes do Termux (um apt adaptado): pkg update, pkg install python, pkg search vim, pkg list-installed, pkg uninstall …. apt funciona como sinônimo. Instala em $PREFIX, não em /usr. Cola em ref-pkg.
$PREFIX
A "raiz falsa" do Termux: /data/data/com.termux/files/usr. Como o app não pode escrever em /usr do Android, tudo é instalado embaixo do $PREFIX ($PREFIX/bin já está no PATH). No Termux real, echo $PREFIX mostra o caminho.
proot / proot-distro
proot é a ferramenta que faz um Linux rodar dentro de outro sem root (só com chamadas de sistema "enganadas"). O proot-distro usa isso para instalar distros completas: proot-distro list mostra ubuntu-24.04 e proot-distro login ubuntu entra num Ubuntu com apt próprio, prompt root@localhost:~# — mas sem root de verdade no Android. Aula proot-distro.
root / su
Root = o superusuário do sistema (uid 0), capaz de ler/escrever qualquer arquivo. No Android, rootar o aparelho (com Magisk, por exemplo) dá esse poder — e os riscos: apps maliciosos com acesso total, sistema que não boota mais se apagar arquivo errado. No Termux dá para "ser root" dentro do proot (sem perigo) ou via adb root/su num celular rootado (com perigo). Aula root no Android.
sshd (e a porta 8022)
O servidor SSH do pacote openssh: com sshd rodando no Termux, o PC acessa o celular por ssh ana@192.168.1.42 -p 8022. A porta padrão no Termux é a 8022 (a 22 exigiria root). Se der Connection refused, o sshd não está no ar — veja cola de erros. Aula sshd no Termux.
Termux
O app que junta tudo: um emulador de terminal + ambiente Linux para Android. Instala um bash real em /data/data/com.termux/files, traz o pkg e pode controlar o celular pela Termux-API. Home: /data/data/com.termux/files/home (o ~). Aula introdução.
Termux-API (pacote + app Termux:API)
O pacote termux-api (instalado com pkg install termux-api) cria os comandos termux-* (bateria, SMS, GPS, câmera, lanterna…), e o app Termux:API (F-Droid) é quem recebe as permissões do Android. Sem os dois juntos, os comandos falham. Cola em ref-termux.
termux-setup-storage / ~/storage
O comando que cria a pasta ~/storage com atalhos para as pastas reais do celular (dcim, downloads, pictures, shared…). Sem ele, ls ~/storage dá Permission denied. Aula storage.
Toast
A caixinha de aviso rápido que aparece no pé da tela do Android por ~2 segundos. Pelo terminal: termux-toast ola → Toast enviado: ola ✓. Diferente da notificação (termux-notification --title …), que fica na barra de status.
Wake lock
O "segura a tela ligada": termux-wake-lock impede o Android de apagar a tela enquanto o script roda (útil para servidores/monitoramento) e termux-wake-unlock libera. Cuidado: esquecido, drena a bateria rapidinho. Aula wake lock.
Wi-Fi adb
Depuração do Android sem cabo: com "Depuração por Wi-Fi" ligada, dá para fazer adb connect 192.168.1.42:5555 e falar com o celular pela rede local — qualquer um na mesma Wi-Fi também pode, se a depuração ficar ligada. Perigoso num aparelho rootado.

Os pares que mais confundem

  • Termux × Termux:API: o Termux é o terminal; o Termux:API é o app que dá permissão para os comandos termux-* controlarem o celular.
  • pkg × apt: sinônimos no Termux — use pkg por costume.
  • root do proot × root do Android: proot-distro login ubuntu mostra root@localhost, mas é root falso (proot); só su/adb root em aparelho rootado é root de verdade.
  • u0_a231 × root: dentro do Termux você é u0_a231 (app comum); via adb shell no celular rootado você vira root.
  • toast × notificação: toast aparece 2s na tela (termux-toast); notificação fica na barra de status (termux-notification).
  • wake lock × tela sempre ligada: o wake lock segura a tela só enquanto o processo roda; o ajuste do Android é permanente.
  • sshd porta 8022 × 22: no Termux usa 8022 (22 exige root); no PC, ssh usa 22.
  • ~/storage × pasta real: ~/storage/shared é atalho para /storage/emulated/0 — mesmo lugar, dois caminhos.

Pratique no terminal simulado

Missão 1 — quem sou eu: rode whoami e veja o app uid da Ana (u0_a231 (ana)). Compare com pwd e uname -a.

Missão 2 — ficha do aparelho: rode termux-info e ache a linha Device: Pixel 7 Pro (rooted). Depois rode adb shell whoami para ver a diferença: root.

Resumo

  • Termux = terminal + Linux no Android; home em /data/data/com.termux/files/home; app uid u0_a231.
  • pkg instala em $PREFIX; repositório termux-main; apps oficiais vêm da F-Droid.
  • termux-* = Termux-API (pacote + app Termux:API com permissões); ~/storage precisa de termux-setup-storage.
  • adb fala com o celular (rootado: vira root); sshd na porta 8022 traz o PC para dentro do celular.
  • proot-distro = Ubuntu dentro do Termux sem root real; ngrok publica o servidor local; termux-wake-lock segura a tela (e a bateria).
