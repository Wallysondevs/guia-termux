sshd no Termux: o celular vira servidor SSH

Agora a brincadeira esquenta: com o sshd rodando, o celular da Ana vira um servidor SSH — e você acessa o terminal dele do PC, pelo Wi-Fi, como se fosse uma máquina remota. Nesta aula: instalar o openssh, trocar a senha (passwd), gerar um par de chaves (ssh-keygen), ligar o servidor na porta 8022 (app comum não abre a 22) e conectar com ssh ana@192.168.1.42 -p 8022.

Você vai aprender
  • Instalar o servidor: pkg install openssh.
  • Por que a porta é 8022 e não 22 (portas abaixo de 1024 exigem root no Android).
  • passwd — trocar a senha do usuário do Termux (obrigatório antes de entrar por SSH).
  • ssh-keygen — gerar par de chaves em ~/.ssh/id_rsa (login sem senha depois).
  • sshd — ligar o servidor; a saída mostra o comando exato para conectar do PC.
  • Descobrir o IP do celular na Wi-Fi com ifconfig (inet 192.168.1.42) e confirmar a porta aberta com nmap localhost.

O plano: PC → Wi-Fi → celular

A topologia é simples: o PC e o celular na mesma rede Wi-Fi. O celular roda o sshd (servidor SSH) na porta 8022; o PC roda o cliente ssh e entra no terminal do celular como se fosse remoto:

$ ifconfig            « no Termux:descobre o IP do celular na Wi-Fi
wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>
        inet 192.168.1.42  netmask 255.255.255.0
        ether dc:a6:32:11:22:33
$ ssh ana@192.168.1.42 -p 8022    « no PC: entra no celular
ana@android:~$ whoami
u0_a231 (ana)

Repare: depois de conectar, o prompt muda para ana@android:~$ — você está dentro do celular, mas digitando no teclado do PC.

Passo 1: instalar o openssh

$ pkg install openssh
The following NEW packages will be installed:
  openssh
0 upgraded, 1 newly installed, 0 to remove.
Setting up openssh (9.6p1) ...
openssh instalado ✓

O pacote openssh traz o cliente ssh e o servidor sshd, além do ssh-keygen e do scp.

Passo 2: trocar a senha com passwd

Sem senha forte, qualquer um da mesma Wi-Fi entra no seu celular. Troque antes de ligar o servidor:

$ passwd
New password: ••••••••
BAD PASSWORD: too short
New password: ••••••••
Senha alterada ✓ (simulado)
"BAD PASSWORD: too short" é o próprio Linux recusando — o Android/Termux avisa porque senha curta em SSH é porta aberta. Use frase longa com números e símbolos (ex.: cafe-com-leite-2024!). E nunca use a mesma senha do bloqueio do celular.

Passo 3: par de chaves com ssh-keygen

Chave assimétrica é mais segura que senha: você gera um par no celular (~/.ssh/id_rsa privada, id_rsa.pub pública) e copia a pública para o PC — aí o login é automático:

Missão: rode ssh-keygen no terminal. A saída deve conter Your identification has been saved — a chave privada ficou em ~/.ssh/id_rsa.

$ ssh-keygen
Gerando par de chaves RSA 4096...
Your identification has been saved in /data/data/com.termux/files/home/.ssh/id_rsa.
Fingerprint: SHA256:TermuxAna123
ssh-keygen
Gera o par de chaves (padrão RSA 4096).
~/.ssh/id_rsa
A chave privada — fica no celular, nunca compartilhe.
~/.ssh/id_rsa.pub
A chave pública — essa você copia para o PC (ssh-copy-id faz isso).

Passo 4: ligar o sshd na porta 8022

Agora ligue o servidor:

Missão: digite sshd e aperte Enter. A saída deve mostrar sshd rodando ✓ e o comando para conectar do PC: ssh ana@192.168.1.42 -p 8022.

$ sshd
Iniciando sshd na porta 8022...
sshd rodando ✓ — conecte do PC com:
  ssh ana@192.168.1.42 -p 8022

Por que 8022 e não 22? No Linux, só root pode abrir portas abaixo de 1024. Como o Termux roda como usuário comum (u0_a231), o projeto escolheu a 8022 como porta padrão do app — é a mesma lógica do python -m http.server 8080.

Segurança básica de SSH num celular: (1) senha forte ou chave (nunca os dois desligados); (2) se não vai usar de fora de casa, desligue o sshd quando sair (killall sshd); (3) Wi-Fi público + SSH ligado = risco — prefira chave e, se puder, VPN. O nível 3 deste guia aprofunda em segurança.

Do PC: conectar no celular

No notebook da Ana (Linux/macOS; no Windows use o PowerShell/WSL), basta:

$ ssh ana@192.168.1.42 -p 8022
The authenticity of host '[192.168.1.42]:8022' can't be established...
ana@android:~$ pwd
/data/data/com.termux/files/home
ana@android:~$ ls ~/storage
dcim  downloads  movies  music  pictures  shared
ssh
O cliente de terminal remoto (secure shell).
ana@192.168.1.42
usuário no IP do celular (pegue com ifconfig no Termux — campo inet do wlan0).
-p 8022
A porta — obrigatória aqui, porque o padrão seria 22 e o Termux usa 8022.

Na primeira conexão, o PC pergunta se confia na "impressão digital" do servidor (yes) — é normal. Depois, você cai direto no prompt ana@android:~$.

Conferindo: ifconfig e nmap localhost

Dois comandos para confirmar que está tudo no ar:

$ ifconfig
wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>
        inet 192.168.1.42  netmask 255.255.255.0
        ether dc:a6:32:11:22:33

lo: inet 127.0.0.1
$ nmap localhost
Starting Nmap 7.94 (simulado)
Host 192.168.1.42 is up.
PORT     STATE SERVICE
8022/tcp open  ssh
8080/tcp open  http
Nmap done: 1 IP address scanned ✓

O nmap localhost mostra a porta 8022/tcp open ssh — prova de que o servidor está escutando. (O 8080 aparece porque a Ana deixou um servidor web rodando — próxima aula.)

Copiar arquivos entre PC e celular: scp

Com o SSH no ar, o scp leva arquivos de um lado para o outro — perfeito para mandar as fotos do celular para o PC:

$ scp -P 8022 ana@192.168.1.42:~/storage/shared/DCIM/Camera/IMG_20240501.jpg .
IMG_20240501.jpg          100%  312KB   2.1MB/s
$ scp -P 8022 ~/meu-site.zip ana@192.168.1.42:~/projetos/
meu-site.zip              100%   1.2MB   3.4MB/s
Maiúsculo matters: no scp a porta é -P (maiúsculo), mas no ssh é -p (minúsculo). Clássico.

Mais de uma sessão de cada vez: tmux

Conectou pelo PC, desligou a tela do notebook e quando voltou a conexão caiu? O tmux resolve: ele mantém a sessão viva no celular, e você reconecta nela depois:

$ pkg install tmux
tmux instalado ✓
$ tmux new -s ana
« dentro do tmux: tudo que rodar aqui continua vivo se a conexão cair
$ tmux ls
ana: 1 windows (created ...)
« no PC, depois de reconectar:
$ ssh ana@192.168.1.42 -p 8022
ana@android:~$ tmux attach -t ana
« voltou exatamente onde parou

Parando o sshd e o aviso de "host mudou"

$ killall sshd     « desliga o servidor quando não precisar mais
$ sshd              « liga de novo quando quiser

Se você reinstalar o Termux (ou trocar de celular), o PC reclama na próxima conexão:

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
IT IS POSSIBLE THAT SOMEONE IS DOING SOMETHING NASTY!
Esse aviso é sério: o PC guarda a "impressão digital" de cada servidor em ~/.ssh/known_hosts. Se ela mudou, ou o servidor é outro (Termux reinstalado = chave nova), ou alguém está se passando pelo seu celular na rede (ataque "man in the middle"). Para o caso legítimo (reinstalou), apague a linha antiga: ssh-keygen -R [192.168.1.42]:8022 — e só faça isso se tiver certeza de que é o seu aparelho.

Copiando a chave pública para o PC (login sem senha)

Depois do ssh-keygen, mande a chave pública para o PC uma vez — depois entra sem digitar senha:

$ ssh-copy-id -p 8022 ana@192.168.1.42   « pedindo a senha uma última vez
ana@android:~$ exit
« pronto: da próxima vez entra direto com a chave

Resumo do fluxo de chaves: a privada (~/.ssh/id_rsa) fica no celular e nunca sai de lá; a pública (id_rsa.pub) vai para o PC. Quem tem a pública não consegue entrar — só a privada autentica.

Sem digitar IP toda hora: ~/.ssh/config no PC

Em vez de lembrar ana@192.168.1.42 -p 8022, configure um apelido no PC:

Host celular
    HostName 192.168.1.42
    Port 8022
    User ana
    IdentityFile ~/.ssh/id_ana
$ ssh celular
ana@android:~$ whoami
u0_a231 (ana)
« agora é só "ssh celular" — e o scp também entende o apelido:
$ scp celular:~/storage/shared/DCIM/Camera/IMG_20240501.jpg .
IMG_20240501.jpg   100%  312KB

Sincronizando a pasta de projetos: rsync sobre SSH

Com o SSH no ar, o rsync mantém a pasta ~/projetos igual no celular e no PC — só manda o que mudou:

$ rsync -avz --delete -e "ssh -p 8022" ~/projetos/ celular:~/projetos/
sending incremental file list
app.py
meu-site/index.html
sent 4.2K bytes  received 120 bytes
« no celular, depois de rodar o servidor web:
$ rsync -avz -e "ssh -p 8022" celular:~/projetos/ ~/projetos-espelho/
$ rsync -avz -e "ssh -p 8022" ~/projetos/ ana@192.168.1.10:~/projetos/
sending incremental file list
backup.tar.gz
1.204.800 bytes  100%  2.34MB/s
Sincronizado com o PC ✓
rsync -avz
-a modo arquivo (preserva permissões), -v verboso, -z comprime na transferência.
-e "ssh -p 8022"
Diz ao rsync para transportar os dados por um túnel SSH na porta 8022.
--delete
Apaga no destino o que foi apagado na origem — espelha de verdade (cuidado com a direção da seta!).

Endurecendo o sshd: chave sim, senha não

Depois do primeiro acesso, dá para desligar o login por senha no servidor — aí só entra quem tem a chave privada:

$ nano $PREFIX/etc/ssh/sshd_config
« dentro do arquivo, mude:
PasswordAuthentication no
PubkeyAuthentication yes
$ killall sshd && sshd     « reinicia o servidor para valer a config
sshd rodando ✓ — conecte do PC com:
  ssh ana@192.168.1.42 -p 8022
Cuidado ao desligar a senha: se você ainda não copiou a chave pública para o PC (ssh-copy-id), você tranca a porta e perde o acesso. Ordem segura: (1) gere a chave no celular, (2) copie a pública para o PC, (3) teste ssh ana@192.168.1.42 -p 8022 entrando sem digitar senha, (4) só então desligue PasswordAuthentication e reinicie o sshd. Se trancar, a saída é entrar de novo pelo adb (próxima aula) — e como reinstalar o Termux apaga a home, faça backup de ~/.ssh antes de qualquer experimento.

Resumo

  • pkg install openssh traz cliente ssh, servidor sshd, ssh-keygen e scp.
  • Ordem certa: passwd (senha forte) → ssh-keygen (chaves em ~/.ssh/id_rsa) → sshd.
  • O servidor liga na porta 8022 (app comum não abre portas < 1024) e a saída já mostra ssh ana@192.168.1.42 -p 8022.
  • O IP do celular vem do ifconfig (inet 192.168.1.42 no wlan0); o nmap localhost confirma 8022/tcp open ssh.
  • Do PC: ssh ana@192.168.1.42 -p 8022; para arquivos: scp -P 8022 … (P maiúsculo no scp!).
