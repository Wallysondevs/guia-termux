Root no Android: Magisk, su e o adb rootado

O Termux funciona perfeitamente sem root — e essa é uma das coisas mais bonitas dele. Mas o celular da Ana, um Pixel 7 Pro com Android 14, está rootado: o bootloader foi desbloqueado, o Magisk está instalado e o adb consegue subir o daemon adbd como root. Nesta aula você vai entender o que "ter root" significa de verdade, quais os riscos — e como explorar esse poder com segurança a partir do Termux, começando por adb root.

Você vai aprender
  • O que é root no Android: o superusuário root (uid 0) e por que o /system vem montado como somente leitura;
  • O papel do Magisk (patch da imagem de boot, módulos, "hide") e do binário su;
  • Por que root muda o jogo de segurança: apps de banco, OTA, brick e garantia;
  • Como o adb rootado do Pixel 7 Pro entrega um shell root: adb devices, adb root, adb shell whoami, adb logcat;
  • A diferença entre root no Android e root dentro do Termux — e o que o Termux ganha com isso;
  • Praticar tudo no terminal simulado ana@android.

O que é root, de verdade

O Android é um Linux. Como todo Linux, ele tem um superusuário chamado root (uid 0) capaz de ler e escrever qualquer arquivo e terminar qualquer processo. Nos celulares de fábrica esse poder é trancado: a partição /system é montada como somente leitura, não existe o binário su e o daemon adbd (o servidor do adb) roda como um usuário comum. "Ter root" significa exatamente uma coisa: conseguir executar comandos como uid 0.

O caminho clássico para isso é desbloquear o bootloader, gravar uma imagem de boot modificada com o Magisk e instalar o app gerenciador. O resultado prático é o binário su: qualquer app pode chamar su, o Magisk mostra uma caixa de diálogo pedindo permissão e, se você aprovar, o comando roda como root:

$ whoami
u0_a231 (ana)
$ su
# whoami
root
# id
uid=0(root) gid=0(root) groups=0(root)
# uname -a
Linux localhost 5.10.137-android14 #1 PREEMPT
Android 14 · aarch64

Repare na diferença de identidade: dentro do Termux, sem root, whoami responde u0_a231 (ana) — um usuário comum do Android, com acesso apenas ao diretório privado do app (/data/data/com.termux/files) e ao ~/storage compartilhado. Depois do su, o mesmo shell vira root e passa a enxergar o sistema inteiro: /data dos outros apps, processos do sistema, configurações de rádio e por aí vai.

Magisk: o porteiro do root

Hoje o padrão de mercado para root é o Magisk (hoje em dia distribuído como Magisk/KernelSU/APatch, todos com a mesma ideia): ele modifica a imagem de boot do celular para injetar o binário su e um daemon que controla quem pode usá-lo. Toda vez que um app pede root, o Magisk mostra a tela de permissão — é o porteiro. Ele também oferece:

  • Magisk Hide / DenyList: esconde o root de apps específicos (bancos, DRM, jogos) que se recusam a abrir em celular rootado;
  • Módulos:haut om tweaks/plugins que instalam modificaciones de sistema sem tocar na partição /system (que continua verificável e atualizável via OTA em modelos como o Pixel);
  • Zygisk: injeta código em processos no momento da criação, dificultando a detecção.

Ou seja: root hoje não é "tirar a trava do carro", é instalar um porteiro com lista de convidados.

Root tem preço — conheça antes de usar. Com root no celular: (1) muitos apps de banco e DRM detectam e bloqueiam o appareil (use o DenyList do Magisk); (2) as atualizações OTA podem quebrar o root ou até causar bootloop; (3) se algo der errado na partição de boot, o celular pode não ligar mais (brick); (4) a garantia é perdida na maioria dos fabricantes. Regra de ouro: só faça root em aparelho de estudo/backup — nunca no celular do dia a dia do trabalho ou do banco.

O adb rootado do Pixel 7 Pro

Existe um segundo caminho para root que não precisa de su dentro do app: o próprio adb. Em builds de engenharia (e em celulares com root/Magisk que permitem), o comando adb root reinicia o adbd como root. Aí qualquer adb shell abre direto como uid 0 — sem prompt de permissão, sem Magisk no caminho. O Pixel 7 Pro da Ana está assim:

$ adb devices
List of devices attached
R5CT20ABCPIXEL	device product:blueline model:Pixel_7_Pro device:blueline

Dispositivo rootado detectado ✓ (1 dispositivo)
$ adb root
restarting adbd as root
adbd is already running as root ✓
$ adb shell whoami
root
$ adb shell ls /data
(adb shell no Pixel 7 Pro rootado) acesso total a /data ✓
$ adb logcat
--------- beginning of main
I/ActivityManager: Displayed com.termux/.app.TermuxActivity
D/adbd: root shell conectado
adb
o Android Debug Bridge: a ponte entre o PC (ou o próprio Termux) e o daemon adbd que vive no celular
root
pede para reiniciar o adbd como root — só funciona em builds userdebug/eng ou com root (Magisk)
shell
abre um shell no celular; tudo o que vem depois (whoami) roda lá dentro, não no seu terminal local
whoami
pergunta "quem sou eu?" — a prova impressa de que o shell é root

O adb devices também já denuncia o estado: repare na linha R5CT20ABCPIXEL (o número de série do Pixel) seguida de device e na mensagem de dispositivo rootado. Em um celular sem root, adb root responde adbd cannot run as root in production builds — é esse erro que confirma que o seu não está rootado.

Root no Android × root dentro do Termux

Vale separar duas coisas que se confundem:

Termux sem root (padrão)Android com root (Magisk/adb)
Identidadeu0_a231 — usuário comum do Androidroot (uid 0) via su ou adb shell
Acesso a arquivosSó /data/data/com.termux/files e ~/storageO sistema inteiro, inclusive /data dos outros apps
Portas baixas / rede cruaNão pode (limitação do usuário comum)Pode capturar pacotes, mudar MAC, abrir portas < 1024
RiscoMínimo — o Termux é um app como outro qualquerTotal: root ignora as proteções do Android
Quando usar95% do tempo: pkg, servidores, automaçãoEstudo, recuperación de dados, labs, tunning

O Termux em si não precisa de root para quase nada: o pkg instala programas no diretório privado do app, o sshd abre a porta 8022 e a Termux-API conversa com os apps do Android por intents. Root entra na conta para ir além: ler o /data de outros apps via adb shell, inspecionar o logcat completo, instalar um kernel com suporte a captura de pacotes, ou rodar distribuições com proot-distro com mais privileges. Pense no Termux como sua casa (sem root basta) e no root do Android como a chave do condomínio inteiro.

$ termux-info
TERMUX_VERSION=0.118.0
ANDROID_VERSION=14
CPU: Snapdragon 8 Gen 2
RAM total: 8 GB
Storage: 128 GB
Shell: /data/data/com.termux/files/usr/bin/bash
Device: Pixel 7 Pro (rooted)

O próprio termux-info entrega o diagnóstico: repare na última linha, Device: Pixel 7 Pro (rooted) — o simulador (assim como apps de diagnóstico reais) consegue detectar o root.

Como saber se um celular está rootado

Antes de usar root, dá para diagnosticar o appareil por vários sinais — alguns Delphi dentro do próprio Termux, outros via adb. No Pixel da Ana, a soma deles entrega o diagnóstico:

SinalComandoPixel 7 Pro rootado (Ana)Celular comum
Bootloader desbloqueadoadb shell getprop ro.boot.verifiedbootstateorange (unlocked)green (locked)
adbd como rootadb root + adb shell whoamirootusuário comum / erro "cannot run as root"
Binário su presenteadb shell which sucaminho do su (Magisk)não encontrado
App Magisk instaladoadb shell pm list packages | grep magiskcom.topjohnwu.magisknada
Systemlessadb shell su -c 'ls /system'partição intacta, root "systemless"somente leitura
Diagnóstico no Termuxtermux-infoPixel 7 Pro (rooted)modelo sem o selo

O detalhe mais elegante é o root "systemless" do Magisk: ele não modifica a partição /system (por isso ela continua passando na verificação de integridade e as OTAs instalam), e sim monta uma camada por cima dela em tempo de boot. É por isso que dá para ter root e /system verificado no mesmo aparelho.

O tsu do próprio Termux

Se o seu celular tem root via Magisk, o Termux ainda oferece um comando extra: o pacote tsu (pkg install tsu) instala um su dentro do próprio ambiente do Termux, permitindo que scripts do Termux peçam root sem sair do app. O fluxo é o mesmo do su normal — o Magisk mostra a permissão — mas a sessão continua dentro do Termux, com acesso ao $PREFIX e aos seus projetos:

$ pkg install tsu
...
tsu instalado ✓
$ tsu
# whoami
root
# ls /data/data/com.whatsapp
(adb shell no Pixel 7 Pro rootado) acesso total a /data ✓

Repare no poder (e no perigo) disso: com root, o Termux consegue ler o /data de outros apps — coisa que um usuário comum jamais conseguiria. Use isso para estudo, backup e recuperação de dados; jamais para invadir a privacidade de outra pessoa no aparelho.

Root não é sinônimo de anonimato. Com root você aumenta a superfície de ataque: qualquer app com permissão de root aprobada por engano pode ler tudo. No Magisk, revise a lista de apps com root concedido (app do Magisk → aba Superusuário) e revogue o que não usa. E no Termux, prefira o princípio do menor privilégio: rode o dia a dia como ana e só chame su/tsu quando o comando realmente precisar.

Pratique no Pixel 7 Pro rootado

Nos terminais abaixo (máquina ana@android, Pixel 7 Pro com adb rootado), confirme a cadeia inteira do root via adb:

Missão: rode adb devices para ver o Pixel (R5CT20ABCPIXEL) e depois adb root para subir o adbd como root. A saída deve terminar com adbd is already running as root ✓.

Missão: abra um shell no celular com adb shell whoami e confirme que a resposta é root. Compare com o whoami dentro do Termux (u0_a231 (ana)).

Missão: rode termux-info e encontre a linha Device: Pixel 7 Pro (rooted) junto com o hardware (Snapdragon 8 Gen 2, 8 GB de RAM). Também vale adb logcat para ver root shell conectado.

Resumo

  • Root = executar comandos como root (uid 0); no Android de fábrica isso é bloqueado (/system só leitura, sem su).
  • Magisk é o porteiro moderno do root: instala o su, controla permissões por app e permite esconder o root (DenyList).
  • Riscos reais: apps de banco/DRM, OTA, brick e garantia — root só em aparelho de estudo.
  • adb root (builds eng/userdebug ou Magisk) reinicia o adbd como root; adb shell whoami prova com root.
  • O Termux funciona sem root; com root você ganha acesso ao sistema inteiro (/data, logcat, rede crua).
  • termux-info mostra o appareil: Pixel 7 Pro (rooted), Snapdragon 8 Gen 2, Android 14.
