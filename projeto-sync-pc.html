Projeto 3 — sincronizar celular ↔ PC com rsync + sshd

Até aqui os projetos ficaram dentro do celular. Agora a Ana quer que o notebook converse com o celular: mandar o código do bot para o Termux, trazer as fotos do DCIM para o PC e deixar um backup rodando. A ponte é o sshd no celular (porta 8022) + o rsync no PC, que copia só o que mudou — o mesmo protocolo que sincroniza servidores no mundo inteiro. O destino no celular é a pasta ~/storage/shared, que é a raiz da memória interna vista pelo Termux (veja storage).

Você vai aprender
  • A subir o servidor SSH no celular com sshd — porta 8022, IP 192.168.1.42 (aulas: sshd no Termux, segurança).
  • A preparar o acesso seguro: passwd (senha forte) e ssh-keygen (login por chave, sem digitar senha).
  • A enviar e receber arquivos do PC com rsync -avz -e "ssh -p 8022" … ana@192.168.1.42:~/storage/shared/.
  • Por que o IP do celular pode mudar (ifconfig) e como contornar (DHCP fixo no roteador ou apelido no ~/.ssh/config do PC).
  • A montar o fluxo de backup: o script backup.sh no celular + o rsync no PC.

Passo 1 — subir o sshd no celular

O Termux traz o servidor SSH no pacote openssh. A Ana instala e sobe o sshd — ele abre a porta 8022 (no Android, portas abaixo de 1024 exigem root, então o Termux usa 8022 por convenção):

$ pkg install openssh
The following NEW packages will be installed:
  openssh
0 upgraded, 1 newly installed, 0 to remove.
Setting up openssh (9.6p1) ...
openssh instalado ✓
$ sshd
Iniciando sshd na porta 8022...
sshd rodando ✓ — conecte do PC com:
  ssh ana@192.168.1.42 -p 8022

Missão: suba o servidor SSH no simulador: digite sshd — a saída confirma sshd rodando ✓ e mostra o comando de conexão ssh ana@192.168.1.42 -p 8022.

Uma vez no ar, o sshd continua rodando até o celular reiniciar ou o processo morrer — e dá para subir de novo a qualquer momento rodando sshd outra vez (se já estiver no ar, ele avisa). O nmap confirma a porta aberta junto com a do site do projeto 1:

Passo 2 — senha forte e chave SSH (segurança antes de abrir a porta)

Antes de conectar do PC, a Ana blinda o acesso — porque um celular com SSH aberto no Wi-Fi é um alvo (veja chaves SSH, senha forte e criptografia):

$ passwd
New password: ••••••••
BAD PASSWORD: too short
New password: ••••••••
Senha alterada ✓ (simulado)
$ ssh-keygen
Gerando par de chaves RSA 4096...
Your identification has been saved in /data/data/com.termux/files/home/.ssh/id_rsa.
Fingerprint: SHA256:TermuxAna123

Depois ela copia a chave pública para o próprio servidor autorizado (~/.ssh/authorized_keys) — no mundo real, com ssh-copy-id -p 8022 ana@192.168.1.42 rodado do PC. A partir daí o login é por chave, sem digitar senha, e dá para desativar a senha no sshd_config (PasswordAuthentication no) para endurecer ainda mais.

SSH aberto no Wi-Fi público é risco: se o celular estiver com o sshd no ar numa rede pública (shopping, café), qualquer um na mesma rede pode tentar adivinhar a senha. Regras de bolso: senha forte sempre, chave SSH sempre que possível, e se não for usar, mate o sshd (pkill sshd). Nunca exponha a 8022 na internet via ngrok — ao contrário do site estático, SSH dá shell completo.

Passo 3 — conectar do PC e mandar arquivos com rsync

Com o sshd no ar, o PC enxerga o celular como qualquer servidor Linux. Primeiro o teste de conexão e a confirmação do endereço:

$ # comandos rodados no PC (notebook da Ana), não no celular:
$ ssh ana@192.168.1.42 -p 8022
ana@android:~$ whoami
u0_a231 (ana)
ana@android:~$ pwd
/data/data/com.termux/files/home
ana@android:~$ ls
backup.sh  storage  .bashrc  .termux  projetos

O rsync é o canivete suíço da sincronização: ele compara origem e destino arquivo por arquivo (tamanho + data) e transfere somente a diferença — por isso rodar de novo é quase instantâneo. A sintaxe que a Ana usa para mandar a pasta do projeto do PC para o celular:

$ # no PC: manda ~/projetos do notebook para o celular
$ rsync -avz -e "ssh -p 8022" ~/projetos/ ana@192.168.1.42:~/projetos/
sending incremental file list

Passo 4 — o backup que a Ana já tinha: backup.sh + log

O celular da Ana já tem um backup.sh na home — é o script que o projeto de fotos vai agendar. O PC consegue ver e rodar ele por SSH, e o log diz se rodou:

$ cat backup.sh
#!/data/data/com.termux/files/usr/bin/bash
echo "backup iniciado"
tar -czf ~/backup.tar.gz ~/storage/shared/DCIM
echo "backup concluido"
$ cat backup.log
backup iniciado
backup concluido
backup iniciado
backup concluido
$ # no PC: manda o backup compactado do celular para a pasta de backups
$ rsync -avz -e "ssh -p 8022" ana@192.168.1.42:~/backup.tar.gz ~/Backups/celular/
sending incremental file list
backup.tar.gz
1.204.800 bytes  100%  2.34MB/s
Sincronizado com o PC ✓

Esse é o fluxo completo do projeto: o celular roda o backup.sh (compacta o DCIM em ~/backup.tar.gz), e o PC puxa o .tar.gz por rsync/SSH — backup do celular no notebook sem cabo, sem nuvem, só pela rede local.

Passo 5 — o IP muda? apelido no SSH config

Um detalhe chato do mundo real: o roteador pode dar outro IP para o celular a cada reconexão, e aí ana@192.168.1.42 para de funcionar. A solución sem mexer no roteador é um apelido no ~/.ssh/config do PC, depois de conferir o IP atual com ifconfig no celular:

Host celular
    HostName 192.168.1.42
    Port 8022
    User ana
    IdentityFile ~/.ssh/id_rsa
$ # no PC, agora basta:
$ ssh celular
$ rsync -avz -e "ssh" ~/Backups/ celular:~/storage/shared/Backups/

--delete apaga de verdade: rsync --delete faz o destino ficar idêntico à origem — se você mandar a pasta errada, apaga arquivos no celular. Regra: teste primeiro sem --delete (com -n/--dry-run para simular) e só depois habilite.
Mesmo Wi-Fi: celular e PC precisam estar na mesma rede (mesmo Wi-Fi, mesma faixa de IP). Se o ping 192.168.1.42 do PC não responde, ou estão em redes diferentes (ex.: Wi-Fi 2,4 GHz vs 5 GHz separados), ou o firewall do roteador isola dispositivos ("AP isolation").

E um detalhe que salva tempo: no Termux, o sshd precisa ser religado depois de reiniciar o celular (ou quando o app é morto pelo sistema). Muita gente automatiza isso com um script em ~/.termux/boot/ — a mesma ideia do start.sh do projeto do bot.

Resumo

  • O celular vira servidor de arquivos com sshd na porta 8022 — conecte do PC com ssh ana@192.168.1.42 -p 8022 (sshd rodando ✓).
  • Segurança primeiro: passwd com senha forte (Senha alterada ✓) e ssh-keygen para login por chave (Your identification has been saved…), sem senha.
  • rsync -avz -e "ssh -p 8022" origem destino copia só o que mudou, criptografado pelo SSH — termina com Sincronizado com o PC ✓.
  • O destino mágico é ~/storage/shared (= a memória interna, depois do termux-setup-storage): dá para puxar DCIM (fotos) e mandar backup.tar.gz.
  • O IP do celular pode mudar: confira com ifconfig e crie um apelido Host celular no ~/.ssh/config do PC.
  • Cuidado com --delete e teste com --dry-run; celular e PC precisam estar no mesmo Wi-Fi.
