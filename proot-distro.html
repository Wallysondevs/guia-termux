proot-distro: um Ubuntu inteiro dentro do Termux, sem root

O Termux já tem um apt próprio e roda a maioria dos programas Linux. Mas e se você precisar de um Debian/Ubuntu de verdade — com os repositórios oficiais, pacotes que não foram recompilados para Android, ou simplesmente um ambiente idêntico ao do seu servidor? A resposta é o proot-distro: ele baixa um "bootstrap" de uma distro e entra nela com proot (uma camada de翻译 de chamadas de sistema), sem precisar de root. Nesta aula, a Ana instala e entra num Ubuntu 24.04 dentro do próprio celular.

Você vai aprender
  • O que é o proot e por que ele funciona sem root (diferente de um chroot de verdade);
  • proot-distro list: quais distros estão instaladas e quais dá para instalar;
  • proot-distro install debian: baixar e instalar uma distro nova;
  • proot-distro login ubuntu: entrar na distro (o prompt vira root@localhost:~#);
  • Dentro da distro: apt update, instalar pacotes, acessar ~/storage;
  • Quando usar Termux puro vs. proot-distro, e os limites do proot.

O que é o proot (e por que não precisa de root)

Num Linux normal, para isolar um sistema dentro de outro você usa chroot — que exige root. O Android não dá root para apps comuns, então o Termux usa o proot: uma biblioteca que intercepta as chamadas de sistema do programa (open, chroot falso, etc.) e as redireciona, em espaço de usuário. O resultado prático: dentro do proot, o Ubuntu "acha" que é o sistema inteiro — com o próprio /etc, o próprio apt e o próprio root — mas tudo acontece dentro do Termux, sem privilégios especiais no Android.

$ pkg install proot
...
proot instalado ✓
$ pkg install proot-distro
...
proot-distro instalado ✓

O pacote proot é a engine; o proot-distro é o comando bonitinho que baixa, instala e entra nas distros. Com os dois instalados, é só usar.

proot-distro list: o que já está instalado

O primeiro comando é ver a lista — na máquina da Ana já existe um ubuntu-24.04 instalado, e dá para instalar outras:

$ proot-distro list
Instaladas:
  ubuntu-24.04
Disponíveis: debian, alpine, archlinux, fedora, void
Instaladas
as distros já baixadas, prontas para entrar com login — no caso, ubuntu-24.04.
Disponíveis
as distros que dá para instalar agora com proot-distro install <nome>.

proot-distro install: baixar uma distro nova

Para instalar, basta passar o nome da lista "Disponíveis". O comando baixa o bootstrap (o sistema de arquivos mínimo da distro), descompacta e confirma:

$ proot-distro install debian
Installing debian...
Downloading bootstrap... done.
debian instalado ✓ — entre com: proot-distro login debian

O bootstrap de uma distro mínima tem algumas dezenas de MB — depois o apt dela baixa o resto pela internet. Repare na dica no fim da saída: depois de instalar, o comando de entrar é proot-distro login <nome>.

Espaço em disco: cada distro ocupa algumas centenas de MB depois de installed + pacotes. Celular com pouco espaço livre vai sentir — cheque com df -h ~ antes de instalar várias distros. E se uma instalação quebrar no meio, proot-distro reset <nome> apaga e recria a distro do zero.

proot-distro login: entrando no Ubuntu

Entrar é o momento mágico: o prompt muda de ana@android:~$ para root@localhost:~# — dentro da distro, você é root (mas um root "de mentira", preso dentro do proot):

$ proot-distro login ubuntu
Entrando no ubuntu...
root@localhost:~# (proot — sem root real, mas com apt completo)
root@localhost:~# apt update
...
root@localhost:~# cat /etc/os-release
PRETTY_NAME="Ubuntu 24.04 LTS"
root@localhost:~# exit
ana@android:~$

Dentro do Ubuntu, tudo é Ubuntu: o apt instala os pacotes dos repositórios oficiais do Ubuntu (apt install htop, apt install python3...), o /etc/os-release confirma a versão, e os arquivos do Termux continuam acessíveis — inclusive ~/storage/shared, se o termux-setup-storage já foi rodado. Para sair, é o exit de sempre, que devolve o prompt ana@android:~$.

Termux puro vs. proot-distro: quando usar cada um

Termux puro (pkg)proot-distro (Ubuntu/Debian)
Pacotesrepositório próprio do Termux, compilados para Android (aarch64)repositórios oficiais da distro — mesmos pacotes do servidor
Rootnão tem root no Androidroot dentro da distro, mas sem root real no Android (proot)
Hardwareacesso direto via Termux-API (câmera, GPS, lanterna)sem acesso ao hardware do Android
Armazenamento~/storage com setupmesmo ~/storage, herdado do Termux
Performancenativo, rápidoum pouco mais lento (camada proot)
Uso típicodia a dia no celular, Termux-API, apps Androidrodar software de servidor idêntico ao VPS, testar tutoriais de Ubuntu
Limites do proot (importante): dentro do proot você não tem root de verdade no Android — não dá para mexer em /system, ler dados de outros apps ou usar hardware diretamente. Também nem todo programa funciona (coisas que precisam de kernel especial, contêineres dentro do proot, algumas operações de rede baixo nível). Para o uso normal — compilar código, rodar um servidor, seguir um tutorial de Ubuntu — funciona perfeitamente.

Missões no simulador

Na máquina ana@android, veja a distro instalada e entre nela:

Missão: liste as distros com proot-distro list — a saída mostra ubuntu-24.04 em "Instaladas" e as disponíveis (debian, alpine, archlinux...). Tente também proot-distro install debian.

Missão: entre no Ubuntu com proot-distro login ubuntu — o prompt muda para root@localhost:~# (proot, sem root real, mas com apt completo).

Gerenciando a distro: reset e várias distros

Dá para ter várias distros ao mesmo tempo — um Ubuntu para o dia a dia e um Alpine (levíssimo) para testar containers:

$ proot-distro install alpine
Installing alpine...
Downloading bootstrap... done.
alpine instalado ✓ — entre com: proot-distro login alpine
$ proot-distro list
Instaladas:
  ubuntu-24.04
  alpine
Disponíveis: debian, archlinux, fedora, void

Se uma distro "quebrou" (pacotes conflitantes, espaço estourado, bagunça geral), não precisa apagar na mão: o proot-distro reset <nome> apaga tudo e recria do bootstrap limpo:

$ proot-distro reset ubuntu
ubuntu resetado ✓
Dentro do proot, o root é de mentira: o prompt root@localhost:~# parece root de verdade, mas é o proot fingindo. Nada dentro da distro alcança o sistema Android real: sem acesso a /system, sem alterar apps instalados e sem privilégios no kernel — os comandos termux-* continuam funcionando (eles conversam com o app Termux:API), mas o resto do Android segue protegido. Se um tutorial mandar você rodar algo como mount ou mexer em /dev, dentro do proot isso falha ou é simulado.

Qual distro escolher?

A lista "Disponíveis" do proot-distro list muda com o tempo, mas o perfil de cada uma é sempre o mesmo:

DistroPerfilMelhor para
ubuntu-24.04LTS, maior repositório, tutoriais infinitosrodar exatamente o que roda no seu VPS Ubuntu
debianestável, enxuta, mãe de muitas distrosservidores leves e scripts que o tutorial manda "apt install"
alpinemínima (~5 MB), usa apk em vez de aptcontainers, testes rápidos, pouco espaço
archlinuxrolling release, tudo recentíssimoquem gosta de viver no limite (e do pacman)
fedora / voidalternativas com outros gerenciadores (dnf / xbps)aprender outros empacotadores

O fluxo completo para começar do zero numa distro nova: proot-distro install ubuntu → proot-distro login ubuntu → dentro dela, apt update && apt upgrade → instalar o que precisar → exit para voltar ao Termux. E se quiser guardar a distro antes de um reset, dá para empacotar a pasta dela (fica em ~/.proot-distro/installed/<nome>) com tar — o mesmo truque do backup.sh.

Storage dentro da distro: a mesma home

Uma dúvida comum: "dentro do Ubuntu, eu vejo as fotos do celular?". A resposta é sim — o proot compartilha a home do Termux, então ~/storage continua valendo lá dentro (depois do termux-setup-storage):

root@localhost:~# ls ~/storage
dcim  downloads  movies  music  pictures  shared
root@localhost:~# ls ~/projetos
backup.sh  notas.txt

Isso é ouro para automação: um script dentro do Ubuntu consegue empacotar a galeria do celular, sincronizar com o PC ou processar as fotos com python — tudo vendo os mesmos arquivos do Termux. O que não é compartilhado é o resto do sistema Android: a distro tem o próprio /etc, o próprio apt e o próprio /root, isolado do Termux.

Login numa distro que não existe: num celular real, proot-distro login nome-que-nao-instalei dá erro e lista as instaladas. O comando certo é sempre proot-distro list primeiro — no simulador, o proot-distro login ubuntu já mostra o prompt root@localhost:~# com a aviso de que é proot.

Um script que usa o Ubuntu dentro do Termux

O uso mais comum do proot-distro na prática é rodar algo que só existe nos repositórios da distro. Em vez de entrar e sair na mão toda vez, dá para chamar direto:

#!/data/data/com.termux/files/usr/bin/bash
# roda um comando dentro do Ubuntu sem sair do Termux
proot-distro login ubuntu --isolated --fix-low-ports -- /bin/bash -c "
  apt update -qq
  apt install -y cowsay
  cowsay 'oi do Ubuntu dentro do Termux!'
"
termux-toast "fim da distro ✓"

Repare no detalhe: proot-distro login ubuntu -- ... executa o comando e já sai, sem mudar o seu prompt — ideal para scripts. No simulador, o equivalente é o proot-distro login ubuntu que vimos, que devolve root@localhost:~#.

Resumo

  • proot-distro roda distros Linux (Ubuntu, Debian, Alpine, Arch...) dentro do Termux usando proot — sem root no Android.
  • proot-distro list mostra instaladas (ubuntu-24.04) e disponíveis; install <nome> baixa a distro.
  • proot-distro login ubuntu entra na distro: prompt root@localhost:~#, apt próprio, arquivos do Termux acessíveis; exit volta.
  • Dentro da distro você tem root de mentira: nada de acesso ao sistema Android real.
  • Use Termux puro para o dia a dia + Termux-API; use proot-distro para software idêntico ao de um servidor Ubuntu/Debian.
  • Cada distro ocupa centenas de MB — cheque df -h ~; proot-distro reset <nome> recria do zero.
