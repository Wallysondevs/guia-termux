pkg e apt: instalar programas no celular

No PC você usa apt install. No Termux, o comando é pkg install — mas por baixo dos panos o pkg é um apt adaptado para o Android: mesmos repositórios no estilo Debian, mesmos comandos, porém com pacotes compilados para o processador do celular (aarch64) e que funcionam sem root. Nesta aula você instala seu primeiro programa (pkg install python), procura pacotes (pkg search), lista os instalados e vê o erro Unable to locate package.

Você vai aprender
  • Por que o Termux tem o pkg e o que muda em relação ao apt do PC.
  • Os repositórios oficiais: packages.termux.dev (canal stable, repositório termux-main).
  • pkg update / pkg upgrade — atualizar a lista e os programas.
  • pkg install python — instalar (saída termina com python instalado ✓).
  • pkg search vim, pkg show, pkg list-installed — pesquisar e inspecionar.
  • O erro Unable to locate package X e as causas reais.
  • apt também funciona como apelido de pkg (com um aviso).

pkg vs apt: o que muda?

O Android não deixa apps modificarem o sistema, então o Termux não pode usar o /usr de verdade. Em vez disso, ele cria o próprio prefixo /data/data/com.termux/files/usr e instala tudo lá dentro. O gerenciador oficial desse ambiente é o pkg — que, na prática, chama o apt por baixo com os repositórios certos:

PC (Debian/Ubuntu)Termux
Comandoapt install …pkg install … (ou apt install … — funciona como apelido)
Onde instala/usr/bin (precisa de root)/data/data/com.termux/files/usr/bin (sem root)
Repositóriodeb.debian.orghttps://packages.termux.dev/apt/termux-main
Arquiteturaamd64 (PC)aarch64 (celular ARM) — o uname -m confirma
Precisa de root?sim (sudo)não — o app já é dono da própria área

Por isso, quando um tutorial de Linux diz sudo apt install python, no Termux vira só pkg install python. Sem sudo — ele nem existe aqui.

Antes de instalar: pkg update

A lista de pacotes fica no celular; antes de qualquer instalação, atualize-a (e de tempos em tempos, faça pkg upgrade para atualizar tudo):

$ pkg update
Get:1 https://packages.termux.dev/apt/termux-main stable InRelease
Reading package lists... Done
Building dependency tree... Done
$ pkg upgrade
Reading package lists... Done
0 packages upgraded, 0 newly installed.

Instalando: pkg install python

O momento clássico. A Ana quer programar em Python no celular:

Missão: digite pkg install python e aperte Enter. A saída deve terminar com python instalado ✓. Depois rode python --version para ver o Python 3.11.9.

$ pkg install python
The following NEW packages will be installed:
  python
0 upgraded, 1 newly installed, 0 to remove.
Setting up python (3.11.9-2) ...
python instalado ✓
$ python --version
Python 3.11.9
pkg
O gerenciador de pacotes do Termux (wrapper do apt com as correções de caminho).

Subcomando "instalar".

O nome do pacote no repositório — é exatamente o nome que aparece no pkg search.

Depois da instalação, o binário já está no PATH (em $PREFIX/bin): é só chamar python. O mesmo vale para nodejs (node --version → v20.11.1), git, vim, curl, nmap, openssh (o sshd da aula seguinte), sqlite, postgresql, nginx, proot…

Procurando pacotes: pkg search e pkg show

Não sabe o nome exato? Pesquise:

$ pkg search vim
vim/stable 9.1.0 vim
$ pkg search ng
nginx/stable 1.25.4 nginx
ngrok/stable 3.12.1 ngrok
$ pkg show vim
Package: vim
Version: 9.1.0
Maintainer: Termux
Description: pacote do repositório Termux (simulado)
  • pkg search termo — lista pacotes cujo nome contém o termo (ex.: vim acha vim);
  • pkg show pacote — ficha técnica do pacote (versão, mantenedor, descrição);
  • pkg list-installed — só os instalados, cada linha com [installed] (aula instalar mostrou).

Quando o nome está errado: Unable to locate package

O erro mais comum de quem está começando:

Missão: rode pkg install pacote-que-nao-existe de propósito. A saída deve ser Unable to locate package pacote-que-nao-existe — e agora você sabe que o nome está errado, não o Termux.

$ pkg install pythom
Unable to locate package pythom
Causas reais de "Unable to locate package": (1) erro de digitação no nome (o exemplo acima: pythom); (2) faltou pkg update depois de instalar o app; (3) o pacote vive em repositório extra (x11-repo, unstable, root-repo) que você ainda não habilitou. Solução: pkg update + pkg search termo para achar o nome exato.

Desinstalando e limpando

$ pkg uninstall nano
Removing nano ...
nano removido.
$ pkg list-installed | grep nano
(sem saída — não está mais instalado)

O pkg uninstall (ou pkg remove) tira o pacote. Para limpar o cache de pacotes baixados e liberar espaço: pkg clean.

Vários pacotes de uma vez + onde eles moram

O pkg install aceita vários nomes na mesma linha — as dependências são resolvidas sozinhas:

$ pkg install vim nano htop tmux rsync
...
vim instalado ✓
nano instalado ✓
htop instalado ✓
tmux instalado ✓
rsync instalado ✓
$ echo $PREFIX
/data/data/com.termux/files/usr
$ ls $PREFIX/bin | head
bash  cat  curl  git  htop  ls  nano  python  rsync  ssh  vim

Todo binário instalado cai em $PREFIX/bin — e esse diretório já está no PATH, por isso você chama python direto, sem caminho completo.

$PREFIX
Variável de ambiente que aponta para a raiz do Termux: /data/data/com.termux/files/usr. É o "usr" particular do app.
PATH
Lista de pastas onde o shell procura comandos — echo $PATH mostra. Se um comando não é achado, ele não está em nenhuma pasta do PATH (ou não foi instalado).

Quando a instalação falha no meio

Espaço insuficiente é comum em celular: o pkg install postgresql baixa dezenas de MB e o Termux vive na memória interna. Sintoma: o download trava em 0% ou dá erro de escrita. Solução: pkg clean (limpa o cache de .deb baixados) e liberar espaço em ~/storage/downloads.
Pacote que não existe no Termux: programas que dependem de systemd, device drivers ou root real (ex.: alguns servidores de banco enterprise, docker-ce oficial) não têm pacote no repositório Termux. A saída é Unable to locate package mesmo com a lista atualizada. Alternativas: usar a versão disponível (ex.: postgresql funciona; nginx funciona) ou rodar dentro do proot-distro (nível 2).
Conflito de pacote: se você instalou algo por fora do pkg (APK manual, Termux:API de outra fonte), pode dar conflito de assinatura. Remova o app externo e reinstale pelo F-Droid — nunca misture fontes.

Lendo a saída da instalação (anatomia do apt)

Quando o pkg install roda, cada linha da saída tem um significado:

$ pkg install python
The following NEW packages will be installed:   « quais pacotes novos entram
  python
0 upgraded, 1 newly installed, 0 to remove.       « resumo: 1 novo, nada removido
Setting up python (3.11.9-2) ...                  « instalando de fato (versão entre parênteses)
python instalado ✓
  • Get:1 https://packages.termux.dev/… — de qual repositório veio a lista/metadados;
  • The following NEW packages will be installed — se aparecer REMOVED ou not upgraded, o apt está avisando que algo vai mudar além do pedido (leia antes de confirmar com -y);
  • Setting up … — o pacote está sendo configurado (scripts pós-instalação);
  • Erros típicas de rede no meio: Failed to fetch … → rode pkg update e tente de novo.
pkg install -y nome confirma tudo sozinho (bom para scripts). Perigo: em scripts, o -y pula a revisão de quais pacotes serão removidos — se o resumo mostrar to remove com algo que você usa, cancele (Ctrl+C) e instale sem o -y.

Resumo

  • pkg é o apt do Termux: instala em /data/data/com.termux/files/usr, sem root, de packages.termux.dev, para aarch64.
  • Sempre comece com pkg update (Reading package lists... Done) e mantenha com pkg upgrade.
  • pkg install python instala e a última linha é python instalado ✓; o binário já entra no PATH.
  • Para achar nomes: pkg search termo, pkg show pacote, pkg list-installed ([installed]).
  • Erro Unable to locate package X = nome errado, lista desatualizada ou repositório extra faltando.
  • apt install … também funciona (apelido de pkg); pkg uninstall remove.
