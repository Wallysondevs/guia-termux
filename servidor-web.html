Servidor web no celular: python -m http.server 8080

Um comando, e o celular da Ana vira um site na rede local: python -m http.server 8080. Qualquer aparelho na mesma Wi-Fi abre http://192.168.1.42:8080 no navegador e vê os arquivos da pasta atual — fotos, projetos, o que estiver lá. Nesta aula você liga o servidor, descobre o IP do celular com ifconfig, acessa de outro aparelho, para com Ctrl+C e aprende a deixar rodando em segundo plano.

Você vai aprender
  • python -m http.server 8080 — o servidor web de uma linha só (já vem com o Python).
  • A saída Serving HTTP on 0.0.0.0 port 8080 e o que o 0.0.0.0 significa.
  • Descobrir o IP do celular na Wi-Fi: ifconfig → inet 192.168.1.42.
  • Acessar de outro aparelho: http://192.168.1.42:8080 no navegador.
  • Servir a pasta de fotos: cd ~/storage/shared/DCIM/Camera antes de ligar.
  • Parar com Ctrl+C e deixar rodando com tmux / nohup.
  • Limite: é um servidor de desenvolvimento, não de produção (sem HTTPS, sem controle de acesso).

Ligando o servidor

O Python já vem instalado (aula pkg/apt); o módulo http.server é da biblioteca padrão — não precisa instalar nada:

Missão: digite python -m http.server 8080 e aperte Enter. A saída deve começar com Serving HTTP on 0.0.0.0 port 8080.

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
(ctrl+c para parar)
python
O interpretador Python 3.11.9 (instalado com pkg install python).
-m http.server
"rode o módulo http.server" — um servidor HTTP estático embutido na biblioteca padrão.
8080
A porta. Portas abaixo de 1024 exigem root, então no Termux usamos 8080 (o padrão do módulo é 8000).
0.0.0.0
"escute em todas as interfaces de rede" — Wi-Fi, localhost, etc. Se fosse 127.0.0.1, só o próprio celular acessaria.

Enquanto o comando roda, o terminal fica ocupado (é um processo em primeiro plano) e cada acesso imprime uma linha de log:

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
192.168.1.10 - - [24/05/2024 14:32:11] "GET / HTTP/1.1" 200 -
192.168.1.10 - - [24/05/2024 14:32:15] "GET /foto.jpg HTTP/1.1" 200 -

Qual é o meu IP? ifconfig

Para acessar de outro aparelho, você precisa do IP do celular na Wi-Fi. O comando clássico é o ifconfig (ou ip addr):

Missão: rode ifconfig numa caixa nova e ache a linha inet 192.168.1.42 — esse é o endereço do Pixel da Ana na rede local.

$ ifconfig
wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>
        inet 192.168.1.42  netmask 255.255.255.0
        ether dc:a6:32:11:22:33

lo: inet 127.0.0.1

Procure a interface wlan0 (o Wi-Fi): o campo inet traz o IP — no caso da Ana, 192.168.1.42. (lo é o "localhost" interno, 127.0.0.1, que só o próprio celular enxerga.)

O IP pode mudar: cada roteador entrega IPs dinamicamente (DHCP). Se o celular reconectar no Wi-Fi, o IP pode virar 192.168.1.57, por exemplo. Sempre confira com ifconfig antes de conectar — ou configure um IP fixo/DHCP reservation no roteador para o MAC dc:a6:32:11:22:33 do celular.

Acessando de outro aparelho

Com o servidor no ar, pegue o notebook, tablet ou outro celular na mesma Wi-Fi e abra no navegador:

http://192.168.1.42:8080

Vai aparecer uma listagem automática de arquivos (o "directory listing" do http.server) — é a pasta onde o comando foi rodado. Clicou numa foto? O navegador mostra. Clicou num .zip? Ele baixa. Clicou num .mp4? Toca direto no navegador.

Somente o próprio celularhttp://127.0.0.1:8080 (ou localhost:8080)só o Android da Ana
Da internet de foraprecisa de túnel (ngrok) — nível 3/projetosqualquer lugar do mundo

Servindo as fotos: cd antes de ligar

O http.server serve a pasta atual. Então, para mostrar as fotos da câmera na rede, entre na pasta primeiro (com o storage já configurado — aula storage):

$ cd ~/storage/shared/DCIM/Camera
$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
« agora http://192.168.1.42:8080 lista as fotos: IMG_20240501.jpg, VID_20240503.mp4…

Isso é útil para ver as fotos do celular na TV/notebook sem mandar por WhatsApp: liga o servidor na pasta das fotos e abre no navegador da TV conectada na mesma Wi-Fi.

$ cd ~/projetos/meu-site
$ ls
index.html  style.css  foto.png
$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 ...

Também é o jeito padrão de testar um site que você fez no celular antes de subir para a internet: rode o servidor na pasta do projeto e abra no navegador de outro aparelho.

Parando e deixando rodando em segundo plano

O servidor roda em primeiro plano: se você apertar Ctrl+C, ele morre na hora:

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
^C
$ _

Para deixar rodando mesmo fechando o Termux ou perdendo a conexão SSH, use uma das duas Strategien:

$ nohup python -m http.server 8080 > ~/server.log 2>&1 &
[1] 1234
$ cat ~/server.log
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
$ kill %1        « ou: kill 1234 — mata o processo quando quiser parar
$ tmux new -s web
« dentro do tmux:
$ python -m http.server 8080
« pode fechar o app: a sessão tmux continua viva no celular
« para voltar depois: tmux attach -t web
nohup … &
"no hang up": o comando ignora o sinal de desconexão e roda em segundo plano (&).
> ~/server.log 2>&1
Redireciona a saída normal (>) e os erros (2>&1) para o arquivo de log.
tmux
Multiplexador de terminais: mantém sessões vivas mesmo sem tela (ideal no celular).

Conferindo as portas abertas: nmap localhost

Quer saber quais servidores estão rodando no celular agora? O nmap escaneia o próprio aparelho:

$ nmap localhost
Starting Nmap 7.94 (simulado)
Host 192.168.1.42 is up.
PORT     STATE SERVICE
8022/tcp open  ssh
8080/tcp open  http
Nmap done: 1 IP address scanned ✓

8022/tcp open ssh é o servidor da aula sshd; 8080/tcp open http é o servidor web desta aula. O ping básico também confirma que o celular está na rede:

$ ping -c 1 8.8.8.8
PING 8.8.8.8: 56 data bytes
64 bytes: icmp_seq=0 ttl=117 time=23.4 ms
1 packets transmitted, 1 packets received, 0.0% packet loss ✓

Variantes: outra porta, só localhost, e servidor com Node

O http.server aceita opções na hora de ligar:

$ python -m http.server 9000            « outra porta
Serving HTTP on 0.0.0.0 port 9000 (http://192.168.1.42:9000/ ) ...
$ python -m http.server 8080 --bind 127.0.0.1   « só o próprio celular acessa
Serving HTTP on 127.0.0.1 port 8080 ...

Se instalou o nodejs (aula pkg/apt), dá para servir com ele também — útil quando o projeto já é em JavaScript:

const http = require("http");
const fs = require("fs");

http.createServer((req, res) => {
  res.end(fs.readFileSync("index.html"));
}).listen(8080, "0.0.0.0", () => console.log("no ar em 8080"));

$ node server.js
no ar em 8080
« de outro aparelho na Wi-Fi: http://192.168.1.42:8080
Segurança na rede local: qualquer aparelho na mesma Wi-Fi vê o que o servidor serve — inclusive a listagem da pasta se não houver index.html. Se a pasta tiver documentos sensíveis, rode com --bind 127.0.0.1 (só o celular acessa) ou sirva uma pasta só com o que pode ser público. E lembre: HTTP não é criptografado — na Wi-Fi de casa tudo bem; em rede pública, não exponha nada.

Para a internet de verdade: ngrok (preview)

Mais tarde, nos projetos, você vai expor esse servidor para a internet com túnel reverso:

$ pkg install ngrok
$ ngrok http 8080
Forwarding  https://termux-ana-7f3k.ngrok-free.app -> http://localhost:8080
Túnel aberto ✓ — seu site no celular está público na internet

Isso publica http://192.168.1.42:8080 num endereço público HTTPS — igual a um servidor de verdade, saindo do seu bolso.

Testando do próprio celular: curl

Antes de chamar outro aparelho, teste se o servidor responde — o curl faz uma requisição HTTP e mostra a resposta:

$ pkg install curl
curl instalado ✓
$ curl -I http://127.0.0.1:8080
HTTP/1.0  200 OK
Server: SimpleHTTP/0.6 Python/3.11.9
Content-type: text/html
$ curl http://192.168.1.42:8080 | head -8
<!DOCTYPE html>
<html>
<head><title>Directory listing for /</title></head>
<body>
<h1>Directory listing for /</h1>
<hr>

Se o curl responde 200 OK, o servidor está no ar e servindo. Se recusar conexão (Connection refused), o servidor não está rodando (ou está em outra porta).

Erro clássico: "Address already in use" — você ligou o python -m http.server 8080 duas vezes (ou esqueceu que uma sessão tmux já tinha um na 8080). A segunda tentativa morre com OSError: [Errno 98] Address already in use. Solução: mate o processo antigo (Ctrl+C na sessão certa, ou kill %1) ou use outra porta (python -m http.server 8081).
Se outro aparelho não acessa: cheque a trinca — (1) celular e o outro aparelho na mesma Wi-Fi; (2) IP certo (ifconfig no celular, campo inet); (3) porta certa no navegador (:8080). Firewall de roteador bloqueando dispositivo-para-dispositivo é comum em Wi-Fi de visitante — teste primeiro com o curl no próprio celular.

Resumo

  • python -m http.server 8080 liga um servidor web na pasta atual — saída: Serving HTTP on 0.0.0.0 port 8080.
  • 0.0.0.0 = todas as interfaces; o IP real vem do ifconfig (inet 192.168.1.42 no wlan0).
  • De outro aparelho na mesma Wi-Fi: abra http://192.168.1.42:8080 no navegador.
  • Serve o que estiver na pasta: cd ~/storage/shared/DCIM/Camera para fotos, cd ~/projetos/meu-site para um site.
  • Ctrl+C mata o processo; nohup … & ou tmux deixa rodando em segundo plano.
  • É servidor de desenvolvimento (sem HTTPS/acesso restrito); para expor na internet, veja ngrok nos projetos.
  • nmap localhost mostra as portas abertas: 8022/tcp open ssh, 8080/tcp open http.
