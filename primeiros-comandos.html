Seus primeiros comandos no Android

Toda vez que você abre o Termux, cai num prompt ana@android:~$ esperando um comando. Nesta aula você dá os primeiros passos de qualquer Linux — mas vendo o Android por dentro: quem é o usuário do app (whoami → u0_a231), onde fica a home (pwd), o que tem nela (ls), qual kernel está rodando (uname -a → Android 14) e as informações do aparelho (termux-info).

Você vai aprender
  • whoami — quem sou eu no Android: o app roda como usuário próprio (u0_a231 (ana)).
  • pwd — onde estou: a home privada /data/data/com.termux/files/home.
  • ls — o que tem aqui: backup.sh storage .bashrc .termux projetos.
  • uname -a — o kernel Linux do Android (versão, arquitetura aarch64, Android 14).
  • termux-info — o aparelho inteiro: Pixel 7 Pro, Snapdragon 8 Gen 2, 8 GB de RAM.
  • help e o erro command not found — como pedir ajuda e o que acontece com comando errado.

Quem sou eu? whoami

No PC, você provavelmente é ana ou root. No Android, cada app ganha um usuário Linux próprio — e o Termux não é diferente. O primeiro comando de qualquer terminal é se apresentar:

Missão: digite whoami e aperte Enter. A saída deve ser u0_a231 (ana) — o usuário u0_a231 é a "Ana" dentro do Android.

$ whoami
u0_a231 (ana)

O número u0_a231 é o UID que o Android atribui ao app (cada app instalado ganha um: u0_a231, u0_a232…). O Termux mostra o nome legível entre parênteses. Isso explica por que o Termux não consegue ler os arquivos de outros apps: no Linux, cada usuário só entra na própria casa.

whoami
"who am I" — imprime o usuário atual. Um único comando, sem opções.

Onde estou? pwd e ls

O segundo comando responde "em que pasta estou?". No Termux, a home não é /home/ana — é a pasta privada do app:

$ pwd
/data/data/com.termux/files/home
$ ls
backup.sh  storage  .bashrc  .termux  projetos

E o terceiro lista o que tem nessa pasta:

$ ls -la ~
total 20
drwxr-xr-x 2 u0_a231 u0_a231 4096 backup.sh
drwxrwxr-x 2 u0_a231 u0_a231 4096 storage
-rw------- 1 u0_a231 u0_a231  220 .bashrc
drwx------ 3 u0_a231 u0_a231 4096 .termux
drwxr-xr-x 4 u0_a231 u0_a231 4096 projetos
  • backup.sh — script de backup da Ana (você vai conhecê-lo na automação);
  • storage — a pasta-ponte para fotos e arquivos do celular (só funciona depois do termux-setup-storage, aula storage);
  • .bashrc — arquivo de configuração do bash (começa com ponto = arquivo oculto, o ls normal não mostra);
  • .termux — configurações do próprio Termux;
  • projetos — pasta de códigos dela.
Arquivos ocultos: no Linux, arquivos que começam com . (ponto) são ocultos. O ls sozinho não os mostra — use ls -a (ou ls -la para ver detalhes). É lá que moram as configurações: .bashrc, .ssh, .termux…
pwd
"print working directory" — imprime a pasta atual em caminho absoluto.
ls
"list" — lista arquivos da pasta atual.
-la
Opções combinadas: -l (formato longo, com permissões e dono) + -a (mostra ocultos).
~
Atalho para a home do usuário — ls ~ é o mesmo que ls /data/data/com.termux/files/home.

Qual sistema é esse? uname -a

O comando que revela o kernel — e é aqui que o Android aparece de verdade:

Missão: rode uname -a. Na saída, procure a linha que termina com Android 14 — é o kernel Linux do celular da Ana.

$ uname -a
Linux localhost 5.10.137-android14 #1 SMP PREEMPT
Android 14 · aarch64

Leia a saída: Linux localhost 5.10.137-android14 — ou seja, é Linux de verdade, kernel 5.10, compilado para Android 14 (android14 no nome). A arquitetura aarch64 é o processador ARM de 64 bits do Pixel 7 Pro. Isso é útil quando você baixa programas: no Termux você baixa pacotes aarch64, nunca os de PC (x86_64).

ComandoMostraNa máquina da Ana
uname -sSó o nome do kernelLinux
uname -mArquitetura do processadoraarch64
uname -rVersão do kernel5.10.137-android14
uname -aTudo isso juntoinclui Android 14

O aparelho inteiro: termux-info

Além do kernel, o Termux sabe ler as informações do aparelho. É o comando de "ficha técnica" do celular:

$ termux-info
TERMUX_VERSION=0.118.0
ANDROID_VERSION=14
CPU: Snapdragon 8 Gen 2
RAM total: 8 GB
Storage: 128 GB
Shell: /data/data/com.termux/files/usr/bin/bash
Device: Pixel 7 Pro (rooted)

Repare em dois pontos: ANDROID_VERSION=14 (confere com o uname -a) e Device: Pixel 7 Pro (rooted) — neste guia o celular da Ana é rootado, o que abre o caminho do adb com privilégios de root lá na frente (aula adb).

Peça ajuda: help e o comando errado

Esqueceu os comandos? O próprio terminal lista os do simulador:

$ help
Termux simulado (ana@android):
  pkg update | pkg install python | pkg list-installed | pkg search vim
  termux-setup-storage   ls ~/storage
  termux-battery-status | termux-toast 'oi' | termux-notification --title oi
  adb devices | adb root | adb shell whoami
  python -m http.server 8080 | sqlite3 meu.db "select 1;"
  shell: ls cat pwd whoami uname clear echo help exit history

E se você digitar um comando que não existe, o bash avisa na hora:

$ comnado-torto
comnado-torto: command not found (simulado — tente 'help')
"command not found" é o erro mais comum de iniciante e quase sempre é só digitação errada (repare no exemplo acima: "comnado" no lugar de "comando"). Se um comando do guia não funcionar, confira a grafia — e rode help para ver a lista do que existe.

Dicas de navegação no terminal do celular

O Termux no Android tem teclado virtual, então alguns atalhos fazem muita diferença:

AtalhoO que faz
TabAutocompleta comando, arquivo ou pasta (aperte duas vezes para ver as opções)
↑ / ↓Navega pelo histórico de comandos (o seu history)
Ctrl+CCancela o comando que está rodando (o famoso ^C)
Ctrl+LLimpa a tela (igual ao clear)
Ctrl+A / Ctrl+EVai para o início / fim da linha digitada
cd pastaTroca de pasta; cd ~ ou só cd volta para a home; cd - volta para a pasta anterior

Experimente agora: rode cd projetos, depois pwd (vai mostrar /data/data/com.termux/files/home/projetos), depois cd - para voltar. No prompt, a pasta atual aparece depois dos dois pontos: ana@android:~/projetos$.

$ cd projetos
$ pwd
/data/data/com.termux/files/home/projetos
$ cd -
/data/data/com.termux/files/home
$ pwd
/data/data/com.termux/files/home

Lendo arquivos rapidinho: cat, echo e head

Três comandos que você vai usar o tempo todo para inspecionar arquivos sem abrir editor:

$ cat ~/backup.sh
#!/data/data/com.termux/files/usr/bin/bash
echo "backup iniciado"
tar -czf ~/backup.tar.gz ~/storage/shared/DCIM
echo "backup concluido"
$ cat ~/backup.log
backup iniciado
backup concluido
backup iniciado
backup concluido
$ echo "oi do termux"
oi do termux
$ ls ~/storage | head -3
dcim
downloads
movies
cat ARQUIVO
"concatenate" — despeja o conteúdo do arquivo na tela (ótimo para arquivos pequenos, como scripts e logs).
echo TEXTO
Imprime o texto (e variáveis: echo $PWD). Também grava em arquivo com >.
head -3
Mostra só as 3 primeiras linhas — combinado com o pipe |, filtra a saída de outro comando.

O pipe | é o que torna o terminal poderoso: a saída de um comando vira a entrada do próximo. ls ~/storage | head -3 = "liste o storage, mas só me mostre as 3 primeiras linhas".

cat em arquivo grande trava o terminal (mostra tudo de uma vez). Para arquivos grandes, use less arquivo (navegue com setas, q para sair) ou head/tail para ver só o começo/fim: tail -20 ~/backup.log mostra as últimas 20 linhas.

Onde está cada comando? which e $PATH

Quando você digita ls, o shell procura um arquivo executável chamado ls numa lista de pastas (a variável PATH). O which mostra onde cada um está:

$ which ls cat python
/data/data/com.termux/files/usr/bin/ls
/data/data/com.termux/files/usr/bin/cat
/data/data/com.termux/files/usr/bin/python
$ echo $PATH
/data/data/com.termux/files/usr/bin:/data/data/com.termux/files/usr/bin/applets
$ ls /data/data/com.termux/files/usr/bin | wc -l
142

Todos os programas do Termux moram em $PREFIX/bin — por isso o whoami, o pkg e o python funcionam de qualquer pasta. Se um comando dá command not found, ou ele não está instalado (pkg install) ou não está no PATH.

Resumo

  • whoami → u0_a231 (ana): no Android cada app é um usuário Linux próprio (UID u0_a231).
  • pwd → /data/data/com.termux/files/home: a home do Termux é a pasta privada do app.
  • ls → backup.sh storage .bashrc .termux projetos; ls -la mostra também os ocultos (ponto no nome).
  • uname -a revela o kernel real: 5.10.137-android14, arquitetura aarch64, Android 14.
  • termux-info mostra o aparelho: Pixel 7 Pro (rooted), Snapdragon 8 Gen 2, 8 GB de RAM, Termux 0.118.0.
  • help lista os comandos; comando errado → command not found (geralmente erro de digitação).
