Projeto 1 — site no celular acessível de fora (http.server + ngrok)

A ideia deste projeto é simples e poderosa: o seu celular vira um servidor web. A Ana escribe um site HTML estático numa pasta do Termux, sobe com python -m http.server 8080 e, com um túnel ngrok, qualquer pessoa na internet acessa pelo navegador — mesmo estando atrás do Wi-Fi de casa, sem abrir porta no roteador. É o mesmo truque usado para mostrar um projeto para o cliente em 30 segundos.

Você vai aprender
  • A criar a pasta do projeto e o arquivo index.html dentro de ~/projetos/site.
  • A servir a pasta com python -m http.server 8080 — o servidor fica ouvindo em 0.0.0.0:8080 (todas as interfaces).
  • A descobrir o IP do celular no Wi-Fi com ifconfig e a confirmar as portas abertas com nmap localhost.
  • A publicar na internet com ngrok http 8080, que gera uma URL pública https://…ngrok-free.app.
  • Os riscos reais de expor uma porta: o que não publicar (fotos, documentos, bancos).

Passo 1 — criar o site

Todo projeto começa com os arquivos. A Ana cria a pasta ~/projetos/site e dentro dela um index.html mínimo — repare que o conteúdo é HTML puro, servido "como está" pelo servidor do Python (sem PHP, sem banco: é um site estático):

<!doctype html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Site da Ana</title>
</head>
<body>
  <h1>Oi, eu sou um site rodando no celular! 📱</h1>
  <p>Este HTML está em <code>~/projetos/site/index.html</code>
  dentro do Termux de um Pixel 7 Pro — e está sendo servido
  por <code>python -m http.server 8080</code>.</p>
  <p>Acesse de outro dispositivo pelo IP local:
  <code>http://192.168.1.42:8080</code></p>
</body>
</html>

No Termux real, a Ana edita esse arquivo com vim ~/projetos/site/index.html ou nano (veja editores no celular), ou transfere do PC por rsync/scp (isso é o projeto 3, sync celular ↔ PC). O importante é a regra de bolso: o servidor serve a pasta onde ele foi aberto — entonces o index.html precisa estar dentro de ~/projetos/site.

Cuidado com a pasta: se você rodar python -m http.server 8080 dentro de ~, o servidor lista todos os arquivos da home do Termux (incluindo .ssh, .bashrc etc.) para quem acessar. Rode sempre dentro da pasta do projeto — e nunca sirva a home inteira de propósito.

Passo 2 — instalar o Python e subir o servidor

O servidor web aqui é o próprio Python, que já traz um módulo de servidor estático embutido — não precisa instalar nada além do interpretador (veja pkg e apt e servidor web no celular):

$ pkg install python
The following NEW packages will be installed:
  python
0 upgraded, 1 newly installed, 0 to remove.
Setting up python (3.11.9-2) ...
python instalado ✓
$ python --version
Python 3.11.9

Agora é só entrar na pasta do site e subir o servidor na porta 8080:

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
(ctrl+c para parar)
python
o interpretador Python (instalado com pkg install python)
-m http.server
diz ao Python para rodar o módulo http.server como programa — um servidor de arquivos estáticos embutido na biblioteca padrão
8080
a porta em que ele vai ouvir (poderia ser 3000, 5000, 8000…; 8080 é a convenção)
0.0.0.0
"todas as interfaces de rede" — o servidor aceita conexões do Wi-Fi e do localhost, não só da máquina local

Enquanto esse comando estiver rodando, o terminal fica ocupado (o servidor roda em primeiro plano). Para desligar, é Ctrl+C. Para deixar rodando em segundo plano enquanto você mexe em outra coisa, a Ana usa o tmux (pkg install tmux, depois tmux e roda o servidor numa sessão — Ctrl+B depois D para destacar sem matar).

Passo 3 — testar na rede local

Com o servidor no ar, a Ana confere duas coisas: qual é o IP do celular no Wi-Fi e se a porta 8080 realmente abriu. Do próprio celular:

$ ifconfig
wlan0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>
        inet 192.168.1.42  netmask 255.255.255.0
        ether dc:a6:32:11:22:33

lo: inet 127.0.0.1
$ nmap localhost
Starting Nmap 7.94 (simulado)
Host 192.168.1.42 is up.
PORT     STATE SERVICE
8022/tcp open  ssh
8080/tcp open  http
Nmap done: 1 IP address scanned ✓
$ ping -c 1 8.8.8.8
PING 8.8.8.8: 56 data bytes
64 bytes: icmp_seq=0 ttl=117 time=23.4 ms
1 packets transmitted, 1 packets received, 0.0% packet loss ✓

O inet 192.168.1.42 é o endereço do celular na rede local, e o nmap confirma que a porta 8080/tcp está open http (junto com a 8022 do SSH). Agora, de qualquer outro dispositivo na mesma rede — o notebook do sofá, o celular de um amigo conectado no mesmo Wi-Fi — basta abrir o navegador em http://192.168.1.42:8080 e o site da Ana aparece.

"Funciona no meu Wi-Fi" não é público: o IP 192.168.1.42 só existe dentro da rede local. Fora de casa (no 4G, em outra rede), ninguém acessa — e nem dá para abrir porta no roteador sem mexer nele. É exatamente por isso que o passo 4 existe.

Passo 4 — publicar na internet com ngrok

O ngrok cria um túnel reverso: um servidor público dele recebe as requisições e as entrega para a porta 8080 do seu celular, por uma conexão que o próprio Termux abriu (então o roteador nem precisa ser configurado). Primeiro instala, depois abre o túnel (veja VPN, proxy e túnel reverso):

$ pkg install ngrok
The following NEW packages will be installed:
  ngrok
0 upgraded, 1 newly installed, 0 to remove.
Setting up ngrok (3.12.1) ...
ngrok instalado ✓
$ ngrok http 8080
Forwarding  https://termux-ana-7f3k.ngrok-free.app -> http://localhost:8080
Túnel aberto ✓ — seu site no celular está público na internet

A URL https://termux-ana-7f3k.ngrok-free.app é pública: qualquer pessoa, em qualquer lugar, abre essa地址 e vê o index.html que está no celular da Ana. Na conta gratuita do ngrok a URL muda a cada vez que o túnel abre (e aparece uma página intersticial de aviso); com conta paga dá para reservar um endereço fixo.

Missão: abra o túnel público no simulador: digite ngrok http 8080 — a saída mostra Forwarding https://termux-ana-7f3k.ngrok-free.app -> http://localhost:8080 e termina com Túnel aberto ✓.

Missão: suba o servidor web no simulador antes do túnel: digite python -m http.server 8080 — a saída começa com Serving HTTP on 0.0.0.0 port 8080.

Perigo real — o que NÃO publicar: o túnel deixa tudo o que está na pasta servida público na internet, sem senha. Nunca rode o servidor numa pasta com fotos, documentos, bancos de dados, chaves (.ssh) ou o arquivo do bot com o token. Site estático de brincadeira: sim. A pasta ~/storage inteira: nunca. Veja segurança no Termux.
URL gratuita muda: no plano free do ngrok o endereço *.ngrok-free.app é sorteado a cada túnel novo e expira quando você fecha. Para testes e demonstração, perfeito; para algo permanente, use um domínio próprio com túnel pago ou um VPS barato.

Passo 5 — o ciclo completo na prática

Juntando tudo, a sessão da Ana fica assim — repare que o servidor e o túnel ficam os dois ligadaos ao mesmo tempo (em terminais separados, ou numa sessão tmux):

$ python -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://192.168.1.42:8080/ ) ...
(ctrl+c para parar)
$ ngrok http 8080
Forwarding  https://termux-ana-7f3k.ngrok-free.app -> http://localhost:8080
Túnel aberto ✓ — seu site no celular está público na internet
CamadaEndereçoQuem alcança
Local (só o celular)http://localhost:8080só o próprio Termux
Rede local (Wi-Fi)http://192.168.1.42:8080 (IP de ifconfig)qualquer dispositivo no mesmo Wi-Fi
Internet (túnel)https://termux-ana-7f3k.ngrok-free.appqualquer pessoa, em qualquer lugar

Para desligar tudo: Ctrl+C no terminal do servidor e no do ngrok (ou fecha a sessão do tmux). O endereço público morre na hora — o túnel só existe enquanto o comando roda.

Alternativas ao http.server e ao ngrok

O python -m http.server é perfeito para testar e para sites estáticos leves. Para algo mais parrudo no próprio celular, a Ana instala o nginx (pkg install nginx), que serve com performance de servidor de verdade, com diretório raiz configurável em $PREFIX/etc/nginx/nginx.conf. E no lugar do ngrok dá para usar o cloudflared (túnel da Cloudflare, também gratuito, com URL mais estável) — o simulador aceita os dois com a mesma sintaxe: cloudflared tunnel --url http://localhost:8080 abre um endereço *.trycloudflare.com.

Mas para um site que vai ficar no ar de verdade, a lição deste projeto é outra: o celular é ótimo para prototipar e demonstrar, mas para produção você migra o mesmo HTML para uma hospedagem barata (GitHub Pages, Netlify, Vercel) — o conteúdo é idêntico, só o endereço muda. O que você aprendeu aqui — servir uma pasta estática numa porta e expor com túnel — é exatamente o que esses serviços fazem nos bastidores.

Por que a porta 8080? No Android, portas abaixo de 1024 exigem root — por isso o Termux usa 8022 para o SSH e 8080 para web de desenvolvimento. Em produção (Linux/servidor), a porta padrão de HTTP é a 80 e de HTTPS a 443.

Resumo

  • O celular vira servidor web com python -m http.server 8080 rodando dentro da pasta do site — a saída é Serving HTTP on 0.0.0.0 port 8080.
  • ifconfig mostra o IP no Wi-Fi (inet 192.168.1.42) e nmap localhost confirma a porta aberta (8080/tcp open http).
  • O IP local só vale dentro do Wi-Fi; para a internet, ngrok http 8080 abre o túnel https://termux-ana-7f3k.ngrok-free.app (Túnel aberto ✓).
  • O servidor em 0.0.0.0 aceita conexões de qualquer interface — por isso só sirva pastas de projeto, nunca a home ou o storage.
  • Para rodar em segundo plano use tmux; para parar, Ctrl+C. O túnel público morre junto com o comando.
