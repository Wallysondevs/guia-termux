Wake lock: segurar a tela e a CPU ligadas no Termux

Você agendou o backup para rodar de madrugada e subiu um servidor web no celular. Só tem um problema: o Android adora dormir. Depois de um tempo com a tela apagada, ele entra em doze e derruba a CPU — e seus jobs e servidores param no meio. A solução é o wake lock: um pedido para o sistema não dormir enquanto você segura o lock. Pelo terminal, isso é o termux-wake-lock.

Você vai aprender
  • O que é um wake lock e por que o Android entra em doze sem ele;
  • termux-wake-lock: adquirir o lock (Wake lock adquirido ✓);
  • termux-wake-unlock: liberar o lock na hora certa;
  • O caso de uso clássico: servidor/backup de madrugada no celular;
  • Como combinar wake lock + sshd + termux-job-scheduler;
  • O custo: bateria — e como monitorar com termux-battery-status.

O problema: o Android dorme

Quando a tela apaga, o Android começa a economizar agressivamente: reduz a CPU, atrasa jobs e, no modo doze profundo, só acorda o aparelho de tempos em tempos. Para um servidor no celular — ou um backup que precisa terminar às 3h — isso é fatal. O wake lock é um contador que o sistema respeita: enquanto um app segura um wake lock, o dispositivo não entra em doze. O Termux-API expõe isso num comando simples:

$ termux-wake-lock
Wake lock adquirido ✓ (a tela não apaga enquanto segurar)

A partir desse momento, a tela fica acesa e a CPU acordada — o celular vira um servidor de verdade, ligado na tomada. Para devolver o controle ao Android:

$ termux-wake-unlock
Wake lock liberado.
termux-wake-lock
adquire o wake lock (partial, na prática): tela não apaga e CPU não dorme — saída Wake lock adquirido ✓.
termux-wake-unlock
libera o lock: o Android volta a poder desligar a tela e entrar em doze — saída Wake lock liberado.
Quem segura o lock
o app Termux:API segura em nome do Termux; se o processo do Termux morrer, o lock cai junto.
Bateria é o preço: tela acesa + CPU acordada drenam a bateria rápido — o termux-battery-status da aula de Termux-API vai mostrar o "level" caindo. Regra de ouro: só use wake lock com o celular na tomada ("status": "Charging"), e sempre rode termux-wake-unlock quando o trabalho terminar. Um wake lock esquecido é a causa nº 1 de "celular descarregado de manhã".

Caso de uso: servidor de madrugada

O cenário completo que junta tudo que vimos: a Ana quer que o celular dela vire um servidorzinho à noite — sshd ligado (aula de SSH no celular), servidor web python na porta 8080 (aula de servidor web) e o backup agendado (aula de job-scheduler). O script que liga tudo isso de noite e desliga de manhã:

#!/data/data/com.termux/files/usr/bin/bash
# liga o "modo servidor" do celular à noite
termux-wake-lock                 # tela acesa + CPU acordada
sshd                             # SSH na porta 8022
python -m http.server 8080 &     # site na porta 8080
termux-toast "servidor no ar ✓"
# de manhã, depois do backup:
# termux-wake-unlock             # libera o lock
# kill %1 %2                     # mata python e sshd

Rodando isso, o comando termux-wake-lock garante que o python -m http.server 8080 (Serving HTTP on 0.0.0.0 port 8080) e o sshd (sshd rodando ✓, conecte com ssh ana@192.168.1.42 -p 8022) continuem vivos a noite toda, mesmo com a tela apagada. Na máquina da Ana, dá para ver o IP dela na rede local com ifconfig:

$ ifconfig
wlan0: flags=4163
        inet 192.168.1.42  netmask 255.255.255.0
        ether dc:a6:32:11:22:33

lo: inet 127.0.0.1

Ou seja: de outro computador na mesma rede Wi-Fi, basta acessar http://192.168.1.42:8080 ou conectar via SSH na porta 8022 — o celular da Ana virou um servidor de bolso.

Wake lock + jobs agendados

Lembra do aviso da aula de termux-job-scheduler: o job só roda com o Termux vivo. O wake lock resolve exatamente isso — segurando o dispositivo acordado, os jobs do termux-job-scheduler e as linhas do crontab -l (como o backup de 30 em 30 minutos) continuam executando de madrugada. A combinación típica num script de backup noturno:

$ termux-wake-lock
Wake lock adquirido ✓ (a tela não apaga enquanto segurar)
$ termux-job-scheduler --script ~/backup.sh --period 300000
Job agendado (id 1): ~/backup.sh a cada 300000 ms ✓
$ crontab -l
# crontab do Termux (ana@android)
*/30 * * * * ~/backup.sh >> ~/backup.log 2>&1
$ cat backup.log
backup iniciado
backup concluido

E para saber se ainda vale a pena segurar o lock (celular carregando?), cheque a bateria antes:

$ termux-battery-status

Missões no simulador

Na máquina ana@android, segure o wake lock e depois libere:

Missão: adquira o wake lock com termux-wake-lock — a saída confirma Wake lock adquirido ✓ (a tela não apaga enquanto segurar).

Missão: agora libere o lock com termux-wake-unlock — a saída mostra Wake lock liberado. Depois combine: termux-wake-lock, sshd e termux-battery-status.

Monitorando o servidor de noite

Com o wake lock segurado e os serviços no ar, dá para confirmar tudo pelo próprio terminal — IP na rede local, portas abertas e internet:

$ ifconfig
wlan0: ...
        inet 192.168.1.42  netmask 255.255.255.0
$ nmap localhost
PORT     STATE SERVICE
8022/tcp open  ssh
8080/tcp open  http
Nmap done: 1 IP address scanned ✓
$ ping -c 1 8.8.8.8
1 packets transmitted, 1 packets received, 0.0% packet loss ✓

O nmap localhost mostra exatamente o que o servidor de bolso está oferecendo: 8022/tcp open ssh (o sshd) e 8080/tcp open http (o python -m http.server 8080). O ping confirma que a internet do celular está viva. Esse trio — ifconfig + nmap + ping — é o "painel de status" de qualquer servidor, e no Termux ele está a um comando de distância.

Desligando o modo servidor de manhã

Tão importante quanto ligar é desligar — um wake lock esquecido continua segurando a CPU com o celular fora da tomada. Dá para automatizar o desligamento no próprio crontab: a linha abaixo libera o lock todo dia às 7h:

# crontab do Termux (ana@android)
*/30 * * * * ~/backup.sh >> ~/backup.log 2>&1
# modo servidor só durante a noite: liga às 22h, desliga às 7h
0 22 * * * termux-wake-lock && sshd
0 7 * * * termux-wake-unlock
$ crontab -l
# crontab do Termux (ana@android)
*/30 * * * * ~/backup.sh >> ~/backup.log 2>&1

Assim o celular trabalha de noite (backup, servidor) e volta a economizar de dia. Se o celular estiver sem bateria (termux-battery-status sem "status": "Charging"), o ideal é nem segurar o lock — coloque essa checagem dentro do próprio script que liga o modo servidor.

O que o wake lock não faz

É importante saber os limites: o termux-wake-lock impede que a tela apague e a CPU durma, mas não impede que o Android mate o processo do Termux se a memória acabar ou se o fabricante for agressivo com apps em segundo plano. Ou seja: wake lock ≠ imortalidade. Para um servidor sério de madrugada, a combinação mais robusta é:

  • Wake lock segurado (termux-wake-lock → Wake lock adquirido ✓);
  • uma sessão SSH aberta do PC para o celular (ssh ana@192.168.1.42 -p 8022), que mantém o app vivo e ainda deixa você de olho;
  • o app Termux e o Termux:API marcados como "sem otimização de bateria" nas configurações do Android;
  • e o script de desligamento agendado (termux-wake-unlock de manhã) para não gastar bateria à toa.

Resumo

  • Sem wake lock, o Android entra em doze com a tela apagada e mata jobs/servidores — o termux-wake-lock impede isso.
  • termux-wake-lock → Wake lock adquirido ✓ (a tela não apaga enquanto segurar); termux-wake-unlock → Wake lock liberado.
  • Caso de uso clássico: sshd + python -m http.server 8080 + jobs agendados rodando de madrugada no celular.
  • Sempre use com o celular carregando ("status": "Charging" no termux-battery-status) e sempre libere com termux-wake-unlock no fim.
  • O lock cai se o Termux morrer — combine com uma sessão SSH ativa para manter o app vivo.
