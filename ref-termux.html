Cola dos comandos termux-* (Termux-API)

Além de um terminal Linux, o Termux consegue controlar o próprio celular: ler a bateria, mandar SMS, pegar o GPS, tirar foto, acender a lanterna, vibrar e mandar notificações — tudo por comando. Essa mágica mora no pacote termux-api e cada comando começa com termux-. Nesta página está a cola completa, com a saída real de cada um na máquina da Ana (ana@android, Pixel 7 Pro com Android 14).

Você vai aprender
  • Instalar e habilitar a Termux-API: pkg install termux-api + o app Termux:API da F-Droid com as permissões liberadas.
  • Tabela de consulta rápida de todos os comandos termux-* e o que cada um devolve.
  • Os grupos: sistema (termux-info, bateria, storage), avisos (termux-toast, termux-notification, vibração), sensores e dados (termux-sms-list, termux-location, termux-contact-list), hardware (termux-camera-photo, termux-torch), energia (termux-wake-lock) e tarefas (termux-job-scheduler).
  • As pegadinhas: permissão negada no Android, JSON na saída e wake lock que drena bateria.

Antes de tudo: instalar a Termux-API

Os comandos termux-* não vêm prontos: eles são um pacote à parte. Na máquina da Ana o fluxo foi:

$ pkg install termux-api
The following NEW packages will be installed:
  termux-api
0 upgraded, 1 newly installed, 0 to remove.
Setting up termux-api (0.50.1) ...
termux-api instalado ✓
$ termux-battery-status
{
  "level": 87,
  "status": "Charging",
  "temperature": 31.5,
  "plugged": "AC",
  "health": "Good"
}

Dois detalhes importantes: primeiro, instale também o app Termux:API (na F-Droid, não na Play Store) — é ele que recebe as permissões de SMS, localização, câmera etc. no Android; segundo, rode cada comando pelo menos uma vez e aceite a caixa de permissão que aparece no celular. Sem isso, comandos como termux-sms-list falham com permissão negada.

Se o comando termux-* responder command not found: você esqueceu o pkg install termux-api (ou reiniciou o app sem recarregar — rode termux-reload-settings no Termux real). Se responder permission denied vindos do Android, abra o app Termux:API e conceda a permissão pedida.

Sistema: termux-info e termux-battery-status

Comece sempre conhecendo a máquina: termux-info resume o ambiente e termux-battery-status devolve um JSON — dá para filtrar com ferramentas de texto (no Termux real, daria termux-battery-status | grep level):

$ termux-info
TERMUX_VERSION=0.118.0
ANDROID_VERSION=14
CPU: Snapdragon 8 Gen 2
RAM total: 8 GB
Storage: 128 GB
Shell: /data/data/com.termux/files/usr/bin/bash
Device: Pixel 7 Pro (rooted)
$ termux-battery-status
{
  "level": 87,
  "status": "Charging",
  "temperature": 31.5,
  "plugged": "AC",
  "health": "Good"
}

Na máquina da Ana o celular está carregando na tomada (AC) com 87% de bateria e saúde boa — é esse JSON que um script de monitoring leria para mandar um alerta quando o nível cair.

Avisos na tela: toast, notificação e vibração

Úteis para scripts avisarem sem você estar olhando: o toast aparece por 2 segundos no pé da tela, a notificação cai na barra de status e a vibração chama atenção no bolso:

$ termux-toast backup terminou
Toast enviado: backup terminou ✓
$ termux-notification --title Backup
Notificação enviada (simulada): Backup ✓
$ termux-vibrate
Celular vibrou ✓
termux-notification
o comando que manda a notificação
--title
flag que define o título exibido na barra de status
Backup
o texto do título (pode ter espaços se for passado como um argumento só)

Dados do celular: SMS, GPS e contatos

Com permissão concedida no app Termux:API, o terminal lê SMS, GPS e agenda — sempre em JSON, pronto para processar:

$ termux-sms-list
[{"number":"+5511999887766","body":"Seu código é 123456"},{"number":"+5511912345678","body":"Entrega confirmada"}]
$ termux-location
{
  "latitude": -23.5505,
  "longitude": -46.6333,
  "altitude": 760.0,
  "provider": "gps"
}
$ termux-contact-list
[{"name":"Mãe","number":"+5511999887766"},{"name":"Max","number":"+5511912345678"}]

A Ana está em São Paulo (-23.5505, -46.6333, altitude de 760 m, provedor GPS). Dá para cruzar os dados: mandar um toast para o número que aparece no termux-contact-list, ou salvar a localização num log a cada hora.

Permissão do Android é por comando: se termux-sms-list ou termux-location falhar, abra o app Termux:API → permissões e libere SMS/Localização. O Termux em si não pode burlar isso — é o Android quem tranca.

Hardware: câmera e lanterna

A lanterna é um clássico de script de "modo ladrão" (acende quando o celular sai do bolso) e a câmera vira um sistema de vigilancia DIY:

$ termux-camera-photo ~/foto.jpg
Foto salva em /data/data/com.termux/files/home/foto.jpg ✓ (312 KB)
$ termux-torch on
Lanterna ligada ✓
$ termux-torch off
Lanterna desligada ✓

O caminho longo /data/data/com.termux/files/home/foto.jpg é a casa da Ana dentro do app Termux — é o mesmo que ~/foto.jpg, só que escrito por extenso. Com o termux-setup-storage feito, dá para salvar direto na galeria: termux-camera-photo ~/storage/dcim/foto.jpg.

Energia e tarefas: wake lock e job-scheduler

Dois comandos que resolvem problemas do dia a dia — e um deles pode virar vilão:

$ termux-wake-lock
Wake lock adquirido ✓ (a tela não apaga enquanto segurar)
$ termux-job-scheduler --script ~/backup.sh --period 300000
Job agendado (id 1): ~/backup.sh a cada 300000 ms ✓
$ crontab -l
# crontab do Termux (ana@android)
*/30 * * * * ~/backup.sh >> ~/backup.log 2>&1
Wake lock esquecido drena a bateria: segurar a tela ligada consome energia o tempo todo. Sempre combine com termux-wake-unlock no fim do script — a Ana já tomó um susto com o celular descarregando em 2h por causa disso. Veja a página Wake lock e termux-services.

O termux-job-scheduler roda um script a cada N milissegundos sem precisar de cron (o crontab -l acima mostra a alternativa clássica: a cada 30 minutos o ~/backup.sh roda e grava no backup.log).

Storage: o primeiro termux-* de todos

O termux-setup-storage é o comando que abre o celular para o Termux: ele cria a pasta ~/storage com atalhos para as pastas reais do Android e pede a permissão na hora:

$ termux-setup-storage
Setting up storage access...
Links criados em ~/storage:
  dcim -> /storage/emulated/0/DCIM
  downloads -> /storage/emulated/0/Download
  pictures -> /storage/emulated/0/Pictures
  music -> /storage/emulated/0/Music
  movies -> /storage/emulated/0/Movies
  shared -> /storage/emulated/0
Storage configurado ✓ (aceite a permissão no Android)
$ ls ~/storage
dcim  downloads  movies  music  pictures  shared

Sem esse comando, ls ~/storage responde Permission denied — erro que está na cola de erros.

Pratique no terminal simulado

Missão 1 — bateria: rode termux-battery-status e encontre o nível da bateria da Ana no JSON ("level": 87).

Missão 2 — câmera: tire uma foto pelo terminal com termux-camera-photo ~/foto.jpg e veja o caminho onde ela foi salva. Depois experimente termux-torch on, termux-toast ola e termux-sms-list.

Resumo

  • Comandos termux-* vêm do pacote termux-api + app Termux:API com permissões liberadas.
  • Sistema: termux-info, termux-battery-status (JSON), termux-setup-storage (~/storage).
  • Avisos: termux-toast, termux-notification --title …, termux-vibrate.
  • Dados: termux-sms-list, termux-location, termux-contact-list — tudo em JSON.
  • Hardware: termux-camera-photo ARQUIVO, termux-torch on|off.
  • Energia/tarefas: termux-wake-lock/termux-wake-unlock (cuidado com a bateria!) e termux-job-scheduler --script … --period ….
